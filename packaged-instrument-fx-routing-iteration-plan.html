Playable Package FX and Routing

Preserve authored curated-DSP slots and canonical zone, group, and master routing when a project is compiled into a playable .drpkg, then reconstruct the same immutable DSP graph when that package is opened.

Status: proposed Estimate: 6-10 engineering days Runtime instrument schema: v4 DSP package reader: v2 No new binary record kind

Executive Summary

Outcome first
4 Known package pipeline seams currently discard or reject the graph.
3 Supported DSP ownership scopes: zone, group, and instrument/master.
0 New DSP algorithms required; execution already exists in the curated renderer.
1-2 wk Expected production delivery including compatibility and host validation.
Core conclusion: this is a vertical persistence and activation iteration, not a new audio-engine initiative. Authoring, snapshot validation, graph compilation, scoped rendering, effect state, and realtime activation already exist. The work is to stop the package compiler from dropping that state and stop the package loader from rebuilding a dry, master-only snapshot.

Persist the authored graph

Add ordered FX slots and routing buses to RuntimeInstrumentModel, together with the group-to-bus assignment needed to restore group routes.

Fail closed

A DSP-bearing package that cannot reconstruct or compile its graph must fail playback compatibility. It must never silently open as a dry instrument.

Reuse the live path

Hydrate the existing immutable snapshot structures and let the qualified DspGraphPlan and DspRenderGeneration paths execute them.

Target Runtime Contract

Instrument schema v4

A DSP-bearing runtime instrument must contain all immutable information needed to reconstruct the same graph without consulting the source .drsproj. The existing runtimeInstrument package record remains authoritative; no project authoring payload and no new package record kind are introduced.

PX-01 schema freeze: instrument v4 requires explicit fxSlots and routingBuses arrays plus routingBusId on every group. These fields are required even when an array is empty; v1-v3 alone retain the implicit empty-graph and master-routing behavior. 
{
  "schemaName": "drs.instrument",
  "schemaVersion": 4,
  "groups": [
    {
      "id": "piano",
      "name": "Piano",
      "gainDb": 0.0,
      "routingBusId": "bus-group-piano"
    }
  ],
  "fxSlots": [
    {
      "id": "room",
      "displayName": "Room",
      "effectType": "drs.algorithmicReverb",
      "effectVersion": 1,
      "bypassed": false,
      "parameters": [
        { "id": "decaySeconds", "value": 2.5 },
        { "id": "mix", "value": 0.18 }
      ]
    }
  ],
  "routingBuses": [
    {
      "id": "bus-group-piano",
      "displayName": "Piano Insert",
      "inputSourceId": "groups/piano",
      "fxSlotIds": ["room"],
      "chainBypassed": false
    }
  ]
}

Stable ordering

FX slot parameter order and each bus's fxSlotIds order are semantic. Serialization, compilation, and loading preserve them exactly.

Canonical ownership

Bus sources remain exactly zones/<id>, groups/<id>, or master. Every slot has exactly one chain owner.

Catalog resolution

Active slots must resolve by effectType and effectVersion and pass parameter and scope validation before activation.

Shared validation requirement: do not create a second, weaker package-only DSP validator. Extract or reuse the authoring snapshot graph hydration and catalog-resolution logic so project Preview, Publish, and package open apply the same ownership, scope, parameter, and resource rules.

Compatibility Policy

Reject before dry fallback

DSP changes audible output, so an older reader must not ignore new graph fields and continue. DSP-bearing exports use runtime instrument schema v4 and require package reader schema v2. Existing dry packages remain valid and load with an empty graph through the direct fast path.

Package Reader Expected result Reason
Existing package schema v1 / instrument v1-v3 Existing reader v1 Loads unchanged Frozen current behavior.
Existing package schema v1 / instrument v1-v3 New reader v2 Loads with empty graph Backward compatibility and direct fast path remain mandatory.
DSP package schema v2 / instrument v4 / minimum reader 2 Existing reader v1 Rejected before activation Prevents silent dry playback.
DSP package schema v2 / instrument v4 / minimum reader 2 New reader v2 Loads and compiles graph Full authored DSP semantics are available.
Instrument v4 with malformed or unresolved active graph New reader v2 Playback compatibility failure Invalid DSP never degrades into an empty graph.
Writer policy: during transition, graph-free exports may continue to use package schema v1 and their existing instrument schema. The writer promotes to package schema v2, minimum reader v2, and instrument v4 only when executable FX slots or authored routing buses are present.
PX-01 review decision: package file formatVersion remains 1. The implementation uses distinct constants for legacy package schema v1, DSP package schema v2, DSP minimum reader v2, and runtime instrument v4; the current production writer/reader default remains on the legacy alias until the later delivery slices are complete.

PX-02

Extend runtime instrument and compiler

Carry the graph through compile without involving package I/O.

  • Add FX slots and routing buses to RuntimeInstrumentModel and RuntimeCompilePlan.
  • Add routingBusId to compiled group metadata or derive it through one documented canonical rule.
  • Promote to instrument schema v4 when the graph is present.
  • Validate identity, catalog version, parameter ranges, scope, ordering, and one-owner rules.

PX-03

Converge both export paths

Project the same graph into both standalone/shared-service and plugin exports.

  • Replace both explicit compatibility blockers with one shared pure project-to-package projection.
  • Copy slots, ordered parameters, buses, bypass state, and group bus assignment into the compile plan.
  • Set package schema and minimum-reader requirements from graph presence.
  • Keep unrelated blockers for macro targets, performance banks, pan, and loops intact.
Estimate 1-2 days Exit Both shells emit byte-equivalent graph metadata for one project fixture.
PX-04

Hydrate and activate package DSP

Rebuild the immutable graph during package open and pass it through the existing performance activation path.

  • Populate snapshot FX slots and routing buses from instrument v4.
  • Restore each group route's authored routingBusId instead of hardcoding master.
  • Resolve curated catalog metadata and compute the same DSP graph and content digests used by authoring snapshots.
  • Reject malformed graphs before activation; preserve the currently active package on replacement failure.
Estimate 1.5-2 days Exit Reopened package creates the same graph plan as its source project.
PX-05

Audio parity and release hardening

Prove that packaging is transparent to routing and curated-DSP output.

  • Compare source-project and reopened-package graph plans, parameter vectors, and deterministic offline renders.
  • Cover zone, group, and master chains; serial order; slot and chain bypass; stateful delay/reverb; mono/stereo input.
  • Run package v1 backward compatibility, v2 reader rejection, lifecycle, host validation, and REAPER qualification.
  • Update the package release gate and compatibility documentation.
Estimate 1.5-3 days Exit All release gates pass with no dry fallback or realtime regression.

Risks and Controls

Known failure modes
High / silent dry load

Older readers ignore graph semantics

Require reader schema v2 for DSP-bearing packages and reject before runtime activation. Never infer that unknown graph data is optional presentation metadata.

High / exporter drift

Plugin and shared service diverge

Move compatibility and graph projection into one pure helper. Both shells should supply paths and lifecycle callbacks, not independently define runtime semantics.

High / routing mismatch

Bus source and group claim disagree

Validate the pair groups/<id> plus group.routingBusId as one invariant and reject orphaned or multiply claimed group buses.

Medium / duplicated policy

Package graph validation becomes weaker

Share graph hydration and catalog resolution with authoring snapshots. Package open should not invent alternative limits, defaults, or compatibility rules.

Medium / digest instability

Ordering changes package identity

Preserve authored chain and parameter order, canonicalize only unordered lookup structures, and include graph data in deterministic snapshot/content digests.

Medium / stateful DSP

Delay or reverb state leaks across activation

Continue creating one bounded DSP generation per activation identity and exercise replacement, cancellation, tail, and retirement behavior in package lifecycle tests.

Definition of Done

Iteration exit gates
G1 / Runtime contract Instrument v4 round-trips every static curated-DSP field and rejects malformed ownership.
G2 / Export parity Standalone and plugin exports no longer reject valid FX/bus projects and produce identical graph metadata.
G3 / Compatibility Existing packages load unchanged; old readers reject DSP-bearing packages through minimum-reader versioning.
G4 / Snapshot parity Source project and reopened package build equivalent FX slots, buses, group routes, graph plans, and digests.
G5 / Audio parity Approved project/package render pairs match at the established deterministic tolerance for all supported scopes.
G6 / Fail closed Missing, corrupt, incompatible, or over-budget graphs fail as playback compatibility errors and never open dry.
G7 / Realtime safety No package-specific allocations, locks, file I/O, graph construction, or effect initialization occur on the audio thread.
G8 / Host qualification Focused tests, package release gate, standalone, VST3, and REAPER validation all pass from a clean build.
