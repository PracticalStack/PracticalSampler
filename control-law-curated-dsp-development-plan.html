Control Laws & Curated DSP Parameter Descriptors

A six-sprint plan to make every exposed control feel musical, remain deterministic across save/publish/reload, and deliver the exact physical value the DSP expects.

Outcome

Musical controls

Group volume spends useful travel around normal mixing levels, reaches silence deliberately, and reserves only a small top segment for boost.

One mapping contract

Authoring, project storage, publication, Perform UI, automation, and DSP callbacks use the same versioned forward and inverse law.

Curated choices

The DSP catalog declares what is valid and recommended; authors see safe choices without needing to understand transfer-function math.

Scope decision: evolve the existing CuratedDspParameterDescriptor. Do not introduce a parallel descriptor. It remains the numeric DSP contract and gains control-law metadata that informs authoring defaults and validation.

Current-state diagnosis

Why volume feels almost binary

The current published macro maps normalized travel linearly across approximately -96 dB to +24 dB. That puts unity gain at 80% travel.

70%-12 dBStill attenuated

What is already correct

The gain DSP accepts physical dB and converts it to amplitude with the standard 10^(dB/20) relationship. That behavior should remain owned by the DSP.

  • The fault is the normalized-control-to-physical-value mapping.
  • The DSP should not know whether input came from a fader, knob, automation lane, or macro.
  • The same dB parameter may need different laws for a mixer fader, EQ gain, or generic modulation.

Descriptor evolution

struct CuratedDspControlRecommendation {
    std::string role;               // "mix", "modulation", "eqGain"
    std::string controlLawId;
    double recommendedMinimum;
    double recommendedMaximum;
};

struct CuratedDspParameterDescriptor {
    // existing: id, unit, min/max, default, smoothing
    std::string defaultControlLawId;
    std::vector<std::string> allowedControlLawIds;
    std::vector<CuratedDspControlRecommendation> recommendations;
};

The exact container types can follow catalog conventions. The contract matters: the descriptor describes allowed behavior; the project stores the resolved behavior; the published binding contains a compiled behavior.

Boundary rule: a parameter unit alone is not enough to select a law. A dB-valued mixer fader, a bipolar EQ gain knob, and a generic dB modulation target have different interaction semantics. Assignment role is therefore part of resolution.

Control-law selection policy

The resolver runs when a control is assigned or deliberately upgraded—not during audio processing. It applies this priority:

  1. Explicit authored override, if the descriptor allows it.
  2. Role-specific descriptor recommendation, such as mix.
  3. Descriptor default law.
  4. Unit-based compatibility fallback for legacy or incomplete descriptors.

Sprint roadmap

Six short sprints keep the change reviewable. Each sprint ends with a shippable contract or vertical slice; later work does not depend on untested mapping assumptions.

Key risks and mitigations

  • Sound changes on open: preserve legacy linear laws until explicit migration.
  • UI/DSP divergence: one shared bidirectional implementation; no copied formulas.
  • Descriptor overreach: use role-specific recommendations, not unit-only selection.
  • Realtime regression: compile strings/metadata before activation into fixed data.
  • Future retuning: publish a new law version; never mutate v1.

Explicit non-goals

  • Changing the gain DSP’s dB-to-linear amplitude math.
  • Exposing arbitrary user-authored transfer curves in this iteration.
  • Building a general modulation graph or replacing macro routing.
  • Silently upgrading existing instruments.
  • Redesigning the entire Perform mixer beyond mapping-related affordances.

Initiative definition of done

  • Group gain has useful travel throughout the fader and unity is clearly marked.
  • DSP continues receiving physical dB values and owns no presentation policy.
  • CuratedDspParameterDescriptor identifies allowed/default/role-recommended laws.
  • Every saved new target contains an explicit versioned law.
  • Legacy projects retain their existing response unless intentionally migrated.
  • Authoring, Perform UI, automation, publication, and recall agree at every anchor.
  • Published callback data is fixed-size and realtime-safe.
  • All 12 Perform control slots work with labels, formatting, reset, and accessibility.
  • Malformed or unsupported laws fail publication without replacing last-known-good state.
  • Standalone and VST3 host regression suites pass.
Recommended release cut: ship the new law automatically for newly authored mixer gain controls, plus the explicit legacy upgrade command. Defer arbitrary curve editing until real instrument-author feedback demonstrates a need.
