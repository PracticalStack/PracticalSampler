Five risks holding back the next phase

A focused review of Decent Rhapsody Studio’s product-owned C++ surfaces, emphasizing host recall, lifecycle safety, data integrity, responsiveness, and hostile or malformed input.

Executive summary

2 critical lifecycle and recall gaps
3 high-impact reliability and data-integrity risks
3/3 targeted baseline tests passed; the gaps are largely untested failure modes

The audio callback architecture is notably disciplined: bounded queues, retirement staging, and dedicated real-time diagnostics are already in place. The largest remaining risks sit around the callback—project ownership, asynchronous jobs, file transactions, and import limits.

Top five findings

Critical

DAW host state does not identify or restore the authored project

The processor serializes only the Phase 1 runtime preset payload. The current authoringProjectFile, authored document, draft revision, and published playback identity are absent. A fresh processor therefore starts from buildInitialAuthoringProject() and restores macros/articulation without reconnecting the instrument the user authored.

User impact

A DAW session can reopen with the right control values but the wrong project/content. Unsaved edits are lost, and even a saved project is not automatically reopened.

Evidence

app/src/plugin/PluginProcessor.cpp:656–670
app/src/plugin/PluginProcessor.h:171–172, 383
engine_adapter/src/EngineFacade.cpp:2091–2097

Recommended change

  • Add a versioned host-state envelope around the preset payload.
  • Persist a project locator, project/content digest, and active published revision—not a duplicate copy of all samples.
  • Implement moved/missing-content recovery and an explicit degraded state.
  • Add a round-trip test that loads a non-reference .drsproj into a fresh processor.

Critical

Detached SFZ import threads have no owner, cancellation, or shutdown barrier

Both shells start an anonymous std::thread and immediately detach it. Component::SafePointer protects the eventual UI callback, but it does not stop the worker, cap concurrency, or guarantee that plug-in code remains loaded while the thread is still executing.

Failure mode

Closing an editor, unloading a plug-in instance, or exiting during a large import can leave work running beyond its owning object. Multiple clicks can also create unbounded concurrent analyses.

Evidence

app/src/plugin/PluginEditor.cpp:985–1029
app/src/standalone/MainComponent.cpp:1044–1088
Editor::~Editor():537–541
MainComponent::~MainComponent():515–521

Recommended change

  • Move imports into an owned job service with a stop token and generation ID.
  • Cancel and join jobs during editor/application destruction and processor unload.
  • Allow only one active review per shell, with progress and cancellation UI.
  • Post immutable results back to the message thread.

High

WAV imports and startup metrics decode complete samples on the message/constructor path

The WAV workflow creates directories, copies every selected file, and drains the decoding queue synchronously from the UI callback. Processor construction also drains an import queue to initialize metrics. Each item decodes the entire file into a JUCE buffer and then copies it again into normalized channel vectors.

User impact

Large multisample batches can freeze the editor, trigger host “plug-in not responding” behavior, and slow scanning/instantiation before the UI is even available.

Evidence

app/src/plugin/PluginEditor.cpp:749–827
app/src/standalone/MainComponent.cpp:810–887
app/src/plugin/PluginProcessor.cpp:1583–1599
engine_adapter/src/SampleImport.cpp:848–935

Recommended change

  • Run copy, fingerprint, metadata read, and decode on the managed import service.
  • Publish per-item progress and keep only lightweight metadata on the message thread.
  • Generate waveform peaks incrementally instead of retaining a second full decoded copy.
  • Make processor construction side-effect-free with respect to sample decoding.
High

Project save is atomic per file, but not atomic across the project/instrument pair

Saving stages both files in temporaries, then commits .drinst first and .drsproj second. If the second replacement fails, the new instrument is left beside the old project. The UI reports failure, but disk state has already changed.

Data integrity impact

Disk-full, antivirus, permission, or transient rename failures can create a mismatched project bundle that appears valid until the next open or publish.

Evidence

app/src/shared/ProjectStorage.cpp:283–330
Instrument commit:317–321
Project commit:323–327

Recommended change

  • Save a versioned bundle directory and atomically switch a single manifest pointer, or use a journaled two-phase commit.
  • Keep recoverable backups until both replacements and a read-back validation succeed.
  • Include a shared generation/content digest in both manifests and reject mismatched pairs on load.
  • Add injected-failure tests for each write and rename boundary.
High

Importers trust file size, decoded dimensions, and include depth without budgets

Manifest and stream loaders read entire files before parsing. Sample import accepts up to INT_MAX frames, multiplies by the reported channel count, allocates the full audio buffer, and duplicates it. SFZ cycle detection is present, but recursive includes have no maximum depth, file count, line count, section count, or total-byte budget.

Reliability and security impact

A malformed or merely oversized file can exhaust memory or stack space and terminate the standalone app or host process. The current checks reject invalid values only after potentially expensive input has already been consumed.

Evidence

engine_adapter/src/RuntimeLoader.cpp:61–67, 1024–1035
engine_adapter/src/RuntimeStream.cpp:31–37, 189–200
engine_adapter/src/SampleImport.cpp:874–935
engine_adapter/src/SfzImport.cpp:168–230, 410–428

Recommended change

  • Define central import budgets for bytes, samples, channels, sections, includes, and diagnostics.
  • Check file sizes and safe multiplication before allocation.
  • Use iterative SFZ traversal with depth and aggregate limits.
  • Return structured “budget exceeded” findings and add adversarial fixtures.

Recommended next major item

Build a unified Project Lifecycle & Import Service

Make one product-owned service responsible for project identity, host recall, bounded background jobs, and transactional persistence. The standalone and plug-in shells should become thin clients of this service instead of maintaining parallel project workflows.

Start with the DAW host-state plan →
1 · Host-state envelope Add project locator/digest, published revision, and recovery status around the existing strict preset payload.
2 · Managed job ownership Introduce a bounded worker queue with cancellation, progress snapshots, generation checks, and deterministic shutdown.
3 · Transactional storage Save and validate a coherent project generation, with rollback/recovery for interrupted writes.
4 · One shell contract Move duplicated open/save/import logic out of the roughly 1.4k-line plug-in and standalone shell components into shared orchestration.
