High finding 03 · Detailed implementation roadmap

Move sample I/O and analysis out of construction and message-thread callbacks

Replace synchronous WAV copying, fingerprinting, full-file decoding, and synthetic startup queue drains with a processor-owned job service. Import analysis will retain metadata and mapping suggestions only; waveform previews will be produced from bounded decode chunks; and the message thread will be limited to request submission, presentation, and validated project commits.

  • Scope: WAV import, startup metrics, waveform peak generation
  • Estimate: 26–36 engineering days
  • Delivery: 7 gated sprints
  • Primary risk: migration without changing import semantics

Target outcome

Responsiveness

Submission is constant-time

File chooser completion captures a request and returns. Directory creation, copying, hashing, inspection, and peak generation occur only on owned background work.

Memory

Analysis is not playback decode

Import decisions retain metadata, findings, and zone suggestions. They do not retain a full AudioBuffer followed by another full normalizedChannels copy.

Instantiation

Construction performs no sample I/O

Processor construction, project replacement, close, and host-state restore publish lightweight metric state without opening, hashing, or decoding sample files.

Confirmed execution paths

Finding validated

Both shells copy files and completely drain AuthoringImportQueue inside the chooser/message callback. Each queue step calls importSampleFile(), which allocates a complete JUCE buffer, reads every frame, and duplicates every channel into vectors. Processor::initializeAuthoringImportMetrics() repeats the same queue drain during construction and several project lifecycle operations.

Scope and boundaries

In scope

  • WAV batch copy, fingerprint, inspection, inference, progress, cancellation, and completion.
  • Processor-owned job lifetime with plugin and standalone clients.
  • Project ID and document-revision validation before a completed import is applied.
  • Startup and project-lifecycle metric publication without sample reads.
  • Incremental waveform peak generation and cache invalidation.
  • Deterministic hooks, responsiveness tests, memory bounds, and failure injection.

Non-goals

  • Do not change filename inference, root-key prompts, warning policy, or round-robin reconciliation semantics.
  • Do not move AuthoringSession mutation off the message thread.
  • Do not replace full decoding required by playback preparation.
  • Do not introduce unbounded worker parallelism or one thread per file.
  • Do not treat timer slicing on the message thread as asynchronous I/O.
  • Do not couple processor construction to availability of project sample files.

Proposed work boundary

1 · SubmitThe shell captures selected files, project identity, base revision, selected group, and destination root.
2 · ScheduleA processor-owned service accepts one bounded request and publishes its generation.
3 · StageThe worker creates a private staging directory and copies sources with byte/item progress.
4 · InspectReaders collect format metadata; hashing and optional peaks stream through bounded chunks.
5 · InferFilename and embedded metadata produce lightweight findings and draft-zone suggestions.
6 · PublishAn immutable, generation-tagged result is made visible; decoded sample frames are absent.
7 · CommitThe message thread revalidates project/revision, resolves prompts, renames staged files, and appends content once.

Reuse the proven lifecycle pattern

Model the new service on the existing processor-owned SfzImportReviewService: RAII clients, one joinable C++17 worker, generation-tagged immutable snapshots, cooperative cancellation, explicit consume, and a processor-destructor shutdown barrier. Share lifecycle conventions and test helpers; keep WAV request/result types separate from SFZ review types.

Data and lifecycle contracts

Inspection result

Lightweight by construction

Contains source identity, fingerprint, format metadata, policy results, filename tokens, findings, and suggested zone. It must not contain an AudioBuffer or normalized channel vectors.

Request identity

Reject stale completion

Every request carries owner ID, generation, project ID, base document revision, destination root, and selected group ID. All must still match before commit.

Terminal states

One explicit disposition

Completed, partially completed, canceled, superseded, failed, and consumed are distinct. Cancellation and failure never mutate the project or leave final destination files behind.

Release acceptance criteria

The finding is closed only when all conditions hold

  • Processor construction opens, hashes, copies, and decodes zero project sample files.
  • Project replace, close, migration, and restore do not drain an import queue.
  • WAV chooser completion performs no directory creation, file copy, fingerprint, reader open, or decode.
  • Authoring queue items contain no duration-sized decoded channel storage.
  • Import inspection preserves current metadata, policy, inference, warning, and root-key behavior.
  • Only one bounded WAV batch is active per processor; no thread is detached.
  • Cancellation is observed inside copy and hash loops and during multi-item processing.
  • Cancel, failure, supersede, and stale completion leave no project mutation or partial final files.
  • Completed imports are applied only after owner, generation, project, root, and revision validation.
  • Plugin and standalone use the same request/result/commit workflow.
  • Responsiveness metrics describe real import jobs and expose an honest idle/not-run state.
  • Waveform peaks are generated asynchronously with memory bounded by chunk size and point count.
  • Rapid selection cannot display peaks from an obsolete source or project revision.
  • Processor/editor teardown joins or terminally resolves every owned request.
  • CI structural counters and the supported-host validation matrix pass.

Risks and controls

RiskControlVerification
Inspection diverges from the full decoder’s metadata behavior. Use the same reader and metadata extraction helpers; split only frame ownership. Golden parity tests across WAV, AIFF, FLAC, embedded root/loop metadata, and policy warnings.
A canceled import leaves copied files that look committed. Use request-private staging and finalization only during validated commit. Failure injection at every filesystem boundary plus scratch-directory inventory checks.
Background completion targets a changed project. Carry and revalidate project ID, content root, base revision, owner, and generation. Project close/open/edit/restore tests while each worker stage is paused.
Waveform requests starve batch imports or vice versa. Define explicit serialization/priority and aggressively supersede obsolete waveform requests. Stress rapid selection during a large batch and assert progress for both work classes.
Time-based CI tests become flaky. Gate forbidden operations and bounded memory with counters; use timing as a secondary platform-aware signal. Repeat tests under debug/release and record percentile diagnostics.
Full playback decode is accidentally weakened. Keep inspection and playback-decode contracts explicit and audit each call site. Prepared-playback, preview, publish, and voice regression suites remain unchanged and audible.
