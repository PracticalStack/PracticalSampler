Focused Piano-Damper Iteration

Replace the CC64 release cliff with continuous damping and catchable release tails.

Preserve sample-positioned MIDI CC64 values from 0 through 127, modulate the release time of already-sounding notes, and let a later pedal-down catch whatever energy remains. Convert the Accurate Salamander live-preset half-pedal opcodes into the native runtime while keeping pedal and sympathetic resonance as a separately scheduled capability.

8–10 engineering days Continuous CC64 Dynamic release Repedaling Salamander live SFZ Legacy binary compatibility No resonance expansion
Recommended delivery: five reviewable slices over 1½–2 weeks. Freeze the control law and red timelines first, then persistence/import, realtime voice behavior, repedaling, and host-level qualification using the actual piano MIDI passage.
Baseline

Why the current passage sounds artificial

The host path retains the incoming CC64 byte, but the performance evaluator immediately converts it to a Boolean transition at 64. The voice pool then stores CC64 as either 0 or 127. Pedal-up moves every deferred voice into one fixed release segment, and a later pedal-down cannot alter or catch that segment.

Contract

Behavior to freeze before implementation

Continuous controller state

  • Every valid CC64 event preserves its exact 0–127 value, sample offset, channel placeholder, and stable input sequence.
  • Pedal-down/up mechanics remain threshold transitions; intermediate changes do not retrigger pedal samples or Round Robin resets.
  • The authored sustain controller and threshold determine binary deferral independently from envelope modulation.
  • Reset restores declared controller defaults; panic still terminates voices immediately.

Release-time modulation

  • For the focused path, effectiveReleaseSeconds = clamp(baseRelease + amount × curve(CC64), 0.001, 100.0).
  • Undefined curve points use linear interpolation between the nearest authored points.
  • With dynamic release enabled, CC64 changes during release update the remaining slope at the event sample.
  • The update preserves the current envelope level: no upward gain jump, restart, or discontinuity is permitted.

Repedaling

  • A still-audible releasing voice remains eligible for dynamic damper updates until completion or stealing.
  • Raising CC64 after damping began lengthens the remaining release from its current level; it does not restore energy already lost.
  • Repedaling does not re-enter attack or sustain, allocate another voice, or emit another authored release event.
  • A finished or stolen voice is not recoverable.

Compatibility

  • Existing projects and instruments default to binary CC64 at threshold 64 with no release modulation; SFZ import applies ARIA's separate sustain_lo default of 0.5 when the opcode is absent.
  • Current pedal-down/up trigger ordering and generation ownership remain unchanged for legacy content.
  • Imported half-pedal declarations opt routes into dynamic behavior explicitly; no behavior is inferred from instrument names.
  • Preview and Performance controller state remain isolated.
Frozen repedal example
note-on C4 → CC64=127 → note-off C4 → CC64=32 → CC64=110
The note enters release exactly once. CC64=32 produces a short, audible damping segment. CC64=110 catches the remaining level and substantially extends its tail. The output never jumps louder, and no second release sample is triggered.
Architecture

Add a small compiled damper contract, not a general modulation matrix

Persist authoring-level damper configuration and compile it into fixed-size route data. The audio path performs only bounded table lookup, interpolation, and envelope-state updates. Parsing, validation, curve construction, string handling, and allocation remain outside the callback.

HP-03
2–3 days / realtime voice behavior

  • Stop rewriting sustain-controller values to 0/127; retain exact controller state across host normalization, performance evaluation, voice-pool routing, reset, and activation.
  • Separate Boolean pedal-transition events from continuous release-control updates so intermediate values never fire duplicate mechanics.
  • Extend SamplerVoice with a click-free, allocation-free release-segment update that preserves current level and authored release shape.

HP-04

Catch still-audible voices safely

  • Prove level continuity under fast 127→0→127 and stair-step controller bursts, including multiple CC changes within one callback.
  • Guarantee one physical note-off, one effective release event, and at most one release-trigger sample regardless of repedal count.
  • Cover repeated pitches, voice stealing, all-notes-off, all-sound-off/reset, transport discontinuity, project replacement, and package close.
Exit: repedaling audibly extends only the remaining tail, cannot revive completed voices, and cannot leak or duplicate semantic events.

Guardrails

Risks and explicit boundaries

Envelope discontinuity

Changing a running duration by resetting counters can click or jump in level. The implementation must preserve the current envelope level and alter only its future trajectory.

Long-tail pressure

Salamander deliberately requests up to 100-second releases. Keep the fixed voice limit and deterministic stealing policy; add pressure diagnostics instead of allocating unbounded voice state.

Semantic duplication

Repedaling must not generate a second logical release or release sample. Physical note state, effective release state, and envelope state remain distinct.

False reference parity

The live preset also contains pseudo pedal-resonance regions and other ARIA modulation. Qualification must isolate note damping and document residual differences honestly.

Deferred: resonance

No new pedal-down resonance, pedal-up resonance, sympathetic string coupling, soundboard model, convolution response, or resonance mixer controls.

Deferred: general modulation

No arbitrary target/source matrix, LFO/envelope controller graph, high-resolution CC, MPE/per-note damper, scripting, or blanket support for every *_onccN opcode.

Acceptance

Definition of done

  1. DRS preserves and applies every sample-positioned CC64 value instead of collapsing the controller to 0/127.
  2. Authored CC64 curves modulate release duration continuously and update already-releasing voices without clicks, gain jumps, or callback allocation.
  3. Repedaling catches the remaining audible tail, does not restore lost energy, and cannot duplicate voices or release events.
  4. The Salamander live-preset note-damping block—sustain_cc, sustain_lo, ampeg_dynamic, ampeg_releasecc64, ampeg_release_curvecc64, and curve points—converts into native persisted behavior.
  5. Existing projects, packages, binary CC64 behavior, pedal mechanics, release triggers, reset behavior, and activation-generation ownership remain compatible.
  6. The reported piano MIDI passage no longer has the artificial early cutoff at intermediate CC64 values in plugin and standalone qualification renders.
  7. Focused unit, timeline, import, schema, package, streaming, host, realtime, regression, and production-build gates are green.
  8. Release evidence explicitly states that pedal and sympathetic resonance remain outside this iteration.
Release decision: ship when continuous damping and repedaling are demonstrably correct on the real passage and the Salamander note regions. Do not hold this iteration open for resonance parity; schedule resonance from its own acoustic behavior, content, DSP, authoring, and qualification contract.
