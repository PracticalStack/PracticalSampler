01 | Product frame

Goal and scope

Creator outcome

Creators can see and work with a stable hierarchy of layers, groups, and zones. A newly imported zone never becomes an orphan: it receives a group and a layer container through the same native contract.

Engineering outcome

Layers are persisted, validated, projected, prepared, and rendered as independent objects. Layer values are combined at runtime; they are not copied into child groups or zones.

Explicit non-goal

This iteration does not infer Soft/Hard layers from the Soft String Spurs SFZ, add macros, or implement amplitude_oncc. Those features consume this contract later.

Scope boundary

All implementation, tests, fixtures, and this plan belong to PracticalSampler/. The sibling _analysis/Rhapsody/ tree is excluded. Existing HTML documentation is not rewritten; this file is the new planning artifact.

02 | Ground truth

Current architecture to extend

Practical Sampler already has a useful group pattern. A zone stores its parent groupId; an authored group stores identity, gain, pan, routing, visibility, and an audition anchor. Group membership is derived from the zone parent relationship, while group routing and group gain remain independent runtime data.

Authoring zoneStores groupId and zone-local playback properties.
Authoring groupStores group identity and group-local gain, pan, routing, and UI state.
Snapshot routeMaterializes group membership as a group route with zoneIds.
Render modelCombines zone, group, and master values without mutating the zone.
Voice / DSPUses the effective route and group-owned processing path.

Layer extension

Repeat this pattern one level higher: add a layerId to each group, add an authored layer object, derive layer membership, and carry layer metadata through the immutable snapshot and prepared playback products.

Why membership belongs on the child

Zones already use the child-side groupId relationship. A child-side layerId on groups keeps one authoritative parent relationship, supports efficient validation, and allows layer member lists to remain derived views.

Reference seams: RuntimeModel.h, AuthoringSession.cpp, PlaybackSnapshot.cpp, and SamplerRenderModel.cpp.

Default group

When a zone enters an import or append path without a group, create a deterministic default group, attach the zone, and use the first valid member as its audition anchor.

Default layer

At the same normalization boundary, create a deterministic default layer and attach the newly created default group. If groups already exist but have no layer, attach those groups to the default layer.

No hidden orphan state

Do not leave an empty layerId or groupId in a schema that claims explicit hierarchy. Validation must reject unresolved parent identities after migration/defaulting.

Stable identity rule

Use default-layer and default-group as preferred seeds. If either ID already exists, use the repository’s existing deterministic unique-ID suffix behavior. IDs must remain stable through save/load and import append operations.

04 | Crossfade behavior

Layer-level crossfade contract

Crossfade is a property of a set of sibling layers, not a property that is copied into every group or zone. The layer route resolves a gain weight for the active driver, then the renderer applies that weight to all zones routed through the layer.

Typed driver

  • none: all eligible layers play at unity, matching the default group behavior.
  • velocity: use the existing velocity crossfade semantics as the first reusable implementation.
  • controller: reserve a typed MIDI CC source for the Soft/Hard use case; the initial target is a normalized CC-driven layer crossfade.

Topology rules

  • Each crossfade set has one driver and one curve in this iteration; linear is the first supported curve.
  • Layer fade-in/fade-out windows must be complete, ordered, and non-overlapping beyond the intended shared window.
  • Ambiguous, missing, or incompatible layer partners produce structured validation findings.
Crossfade runtime:
layerWeight = resolveLayerCrossfade(driverValue, layer.crossfade)
zoneEffectiveGain = zoneGain + groupGain + layerGain + masterGain
renderedAmplitude = zoneAmplitude * linearGain(layerWeight)

Scope guardrail

This iteration establishes the crossfade-capable contract and proves one native runtime path. It does not yet map SFZ amplitude_oncc24/25 to layer controls. That importer work follows after layers, groups, and exposed macros are independently usable.

07 | Risk control

Risks and guardrails

Risk: schema drift

Layers must be added to every serialized and prepared representation together. Use a single schema/version policy and round-trip fixtures across standalone and plug-in loading.

Risk: accidental flattening

Do not add layer gain or pan to every group/zone during normalization. Effective values are calculated at render-route construction, preserving independent authored objects.

Risk: defaulting divergence

SFZ, WAV, append, and migration paths must call the same default hierarchy normalizer. Otherwise the same zone can receive different identities depending on its entry path.

Risk: crossfade scope explosion

Start with one typed driver and linear law per crossfade set. Reject ambiguous topology explicitly; do not silently invent layer partners or crossfade all layers globally.

Compatibility guardrail

Projects without authored layers must render as they do today after migration. A single default layer with neutral values is an organizational wrapper, not a sound-shaping change.

08 | Completion

Release gate

Iteration is complete when

  • Layers are first-class authored, snapshot, prepared, package, and runtime objects.
  • Groups remain independent objects and are members of exactly one layer in the explicit hierarchy.
  • An imported zone without a group receives a default group and default layer deterministically.
  • Existing projects migrate to a neutral default layer without changing their sound or authored group/zone values.
  • Layer gain, pan, routing, and the first crossfade path work without flattening child data.
  • Map and authoring workflows make layer/group membership understandable and editable.
  • Invalid hierarchy and crossfade topology are rejected consistently across load, prepare, publish, and package paths.
  • Focused and clean-checkout Practical Sampler tests pass.

Definition of done

The feature is not complete when a layer appears in the document JSON. It is complete when the layer survives persistence and package projection, contains groups through a validated relationship, remains neutral by default, and can apply a tested crossfade weight to all of its groups in the actual runtime path.
