Authoring UX · Canonical design

Unified Instrument Workspace

One authoring view combines the complete Instrument → Layer → Group → Zone hierarchy, the existing Zone Map, and a context-sensitive inspector. Show Map controls the workspace layout; Show Zones sends the current hierarchy selection to the Map as a zone filter.

Status: Ready for implementation planningRevision: 3.1Date: 21 August 2026Focused foundation: Layer and Group Inspector HLDHistorical implementation: first Structure Viewer iteration
Product decision. Remove the Map | Structure mode switch. Keep the Instrument Structure browser persistent. Show Map reveals or hides the existing Map pane and never changes its contents. Show Zones is a contextual command: it derives scope from the current instrument, layer, group, or zone selection, opens the Map when necessary, filters the existing Zone Map to that scope, and fits the result without changing the active inspector.
01 · Design principles

One place to navigate, see, and edit

Hierarchy is persistent

The Instrument Structure tree is the primary navigation surface in every workbench state. It is never replaced by a Layer editor, Group editor, or alternate viewer.

The Map is scoped on request

Selecting an entity changes the inspector. Invoking Show Zones derives the appropriate descendant-zone filter and publishes it to the Map. The active Map scope remains visible above the canvas.

Selection stays independent

Clicking a zone selects it for editing but does not narrow the Map to that single zone. Scope and edit selection are separate pieces of workspace state.

03 · Scope behavior

Show Zones projects the selection into the existing Map

Map scope has exactly one owner: the instrument, one layer, or one group. Selection alone changes the inspector; invoking Show Zones derives the smallest useful container scope, supplies only its descendant zones to the existing Zone Map, and fits the result.

04 · State model

Scope and edit selection must be separate

StructureScope

  • Kind: instrument, layer, or group.
  • Exactly one stable ID, except instrument root.
  • Determines Zone Map membership.
  • Changed by the Show Zones command, not selection alone.
  • Workspace-only; never dirties the project.
≠

AuthoringStructureSelection

  • Kind: layer, group, or zone.
  • One or more same-type stable IDs.
  • Determines inspector type and edit targets.
  • Zone selection does not alter valid parent scope.
  • Selection-only changes are not transactions.
Three independent states. AuthoringStructureSelection controls the inspector. StructureScope controls which zones the Map receives. MapPaneVisible controls whether the Map consumes layout space. Show Zones may update scope and set pane visibility to true, but Show Map only changes pane visibility.
05 · Map controls

Show Map and Show Zones are deliberately different

Show Map · layout toggle

A persistent toolbar toggle reveals or hides the Map pane. Off gives the inspector the reclaimed workspace; on restores the last scope, zone selection, pan, and zoom. It never changes selection or filtering.

Show Zones · contextual command

An action in the active inspector, structure action bar, and hierarchy context menu. It derives scope from the current entity, ensures the Map is visible, filters the existing Zone Map, and fits the result.

06 · Overlapping zones

Filtering helps; stack access finishes the job

Hierarchy scope reduces unrelated overlap, but intentional stacks can still share identical key and velocity geometry. The tree guarantees access to every zone, while Map adds a compact stack affordance.

Stack badge

A small count appears on coincident or substantially occluded rectangles. The badge is visible only when more than one selectable zone shares the hit region.

Click behavior

Clicking the badge opens a native menu listing zone name, velocity, RR, articulation, and event. Selecting an item changes zone selection without changing scope.

Keyboard behavior

A focused stack supports Next/Previous Zone commands. The inspector and tree reveal the chosen stable ID, and the map keeps every scoped peer visible.

Continue editing

Projection and performance rules

  • Instrument scope includes every zone whose parent group and layer are valid descendants.
  • Layer scope derives groups by group.layerId, then zones by those group IDs.
  • Group scope derives zones directly by zone.groupId.
  • Scope membership, overlap stacks, and normalized geometry are cached by document revision and relevant view filters.
  • The tree uses flattened virtual rows; collapsed descendants do not enter the visible row vector.
  • The Map retains its existing dense paint path and does no hierarchy traversal during paint.
  • No scope, selection, filter, or Show Zones operation performs work on the audio thread.

12 · Acceptance criteria

The unified workspace is successful when

  1. There is no separate Structure Viewer mode or Map | Structure switch.
  2. The Instrument Structure tree remains visible and unchanged when workbench tabs change.
  3. Show Map hides and restores the Map pane without changing scope, filtering, selection, inspector, pan, or zoom.
  4. Show Zones derives the correct instrument, layer, group, or parent-container scope and filters the existing Zone Map to exactly its descendant zones.
  5. Invoking Show Zones opens the Map when hidden, fits the derived scope, and preserves the invoking selection and inspector type.
  6. Clicking a zone changes edit selection and inspector without hiding scoped peers.
  7. The Map retains its existing dense vertical range presentation, minimap, pan/zoom, selection marker, and range-editing behavior.
  8. Layer, Group, and Zone inspectors use one right-side host and contain real editable controls.
  9. Coincident zones are accessible through the tree and a count-backed Map stack affordance.
  10. The expanded 1120 px and compact 820 px layouts preserve a useful Map and readable controls.
  11. Scope, selection, disclosure, filters, and pane visibility remain independent workspace-only state stable by ID.
  12. All edits use validated session transactions with one undo step per gesture.
  13. Keyboard and screen-reader users can distinguish Show Map from Show Zones and understand current scope, selection, hierarchy, and stack candidates.
  14. The 1,700-zone responsiveness baseline remains within the existing message-thread budget.
