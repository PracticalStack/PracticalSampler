Structure Viewer

High-Level Design · Practical Sampler Authoring Workspace · August 2026

Related engineering plan: Structure Viewer Iteration Plan

1. Summary

The Structure Viewer is a second way to view and edit an authored instrument. It presents the complete Instrument → Layer → Group → Zone hierarchy as a column browser with a context-sensitive inspector. It complements the existing Zone Map rather than replacing it.

The Zone Map remains the preferred spatial editor for key and velocity mapping. The Structure Viewer becomes the preferred workspace for hierarchy navigation, comparing zones that overlap, moving objects between parents, diagnosing ambiguous mappings, and editing multiple objects at once.

Core principle: Map answers “where does this zone play?” Structure answers “where does this object belong, what else is beside it, and what properties do these objects share?”

2. Goals

  • Make layers, groups, and zones easy to browse as one coherent hierarchy.
  • Make zones with identical or overlapping key ranges independently visible and selectable.
  • Provide a predictable inspector for layers, groups, single zones, and same-type multi-selections.
  • Support fast batch edits with clear mixed-value behavior and one undo transaction per gesture.
  • Share selection and authoring context with the existing Zone Map and lower workbenches.
  • Scale to production instruments without rendering every row as a heavyweight component.
  • Preserve the existing authored object model; the viewer is not a new hierarchy or data format.

3. Non-Goals

  • Replacing the Zone Map or reproducing all of its direct spatial editing gestures.
  • Changing runtime composition, routing order, project schema, or layer contract semantics.
  • Automatically correcting intentional overlaps.
  • Allowing one edit selection to contain layers, groups, and zones simultaneously.
  • Moving specialized waveform, DSP, macro, routing, or performance editors into the inspector.

4. Location in the UI

The viewer lives in the main Authoring mapping surface as a peer to the Zone Map. A persistent segmented control switches between the two views:

The lower workbench tabs remain available. They are specialized editors; Structure is the hierarchy navigator and batch-editing surface. In the long term, Structure assumes the organizational duties of the separate layer and group lists currently placed around the Map, allowing Map mode to devote more space to the key/velocity canvas.

5. Invocation

5.1 Primary entry point

The user clicks Structure in the Map | Structure switch. The selected mapping view is workspace state and is not persisted as authored project data.

5.2 Contextual entry points

  • Show in Structure from a zone's Map context menu.
  • Reveal in Structure from the Zone inspector.
  • Activate an overlap or collision summary to open Structure at the relevant group.
  • Use an open/reveal action from a layer or group summary elsewhere in Authoring.
  • Use View → Mapping View → Structure in hosts that expose the application menu.

Optional shortcuts may use Ctrl/Cmd+1 for Map and Ctrl/Cmd+2 for Structure, subject to host shortcut testing. Buttons and menus remain the authoritative entry points.

6. Main Interaction Model

The main area uses three related columns. A selection in a parent column determines the children displayed in the next column. The complete path remains visible, avoiding repeated drill-in and back navigation.

Action Result
Select a layer Shows its groups and opens the Layer inspector.
Select a group Shows its zones and opens the Group inspector.
Select a zone Opens the Zone inspector without changing the hierarchy path.
Select several siblings Opens the plural inspector and displays shared or mixed property values.
Activate a row's disclosure/open action Moves keyboard focus into its child column.

6.1 Column sizing

Layers and Groups use compact, resizable columns. Zones receives the greatest width because it contains the range visualization. Column widths and scroll positions are remembered as workspace state. At narrow widths, ancestor columns collapse to named breadcrumb rails and can be temporarily expanded; the active hierarchy path must never become invisible.

6.2 Row content

Row type Primary content Secondary content
Layer Name, selection, visibility Group count, zone count, aggregate key coverage, routing state
Group Stable group tint, name, selection, visibility Zone count, aggregate key coverage, round-robin state, routing state
Zone Name/sample identity and aligned key-range bar Root marker, velocity range, RR position, trigger/event badges, diagnostics

7. Zone Range Presentation

Every zone occupies its own row beneath a shared 128-note keyboard ruler. Key-range bars are aligned horizontally across all rows, so identical and partially overlapping ranges can be compared without one zone obscuring another. A distinct velocity track or compact numeric range accompanies each row.

The first release should favor legibility over miniature two-dimensional maps: a shared key ruler, one key-range bar per row, a root marker, and a separate velocity range. Detailed range manipulation remains available in the Zone Map and inspector.

7.1 Relationship and overlap classification

The viewer may classify related zones using conservative, descriptive labels:

  • Velocity stack: matching key ranges with differentiated velocity ranges.
  • Round-robin stack: compatible ranges assigned to a common RR pool.
  • Potential collision: overlapping key and velocity ranges without an obvious RR, crossfade, or trigger distinction.
  • Exact duplicate: zones whose relevant mapping and trigger conditions appear indistinguishable.

These are navigation aids, not validation errors. Trigger events, articulations, controllers, choke behavior, and intentional layering can make overlapping zones valid. Diagnostic details must explain which fields were compared and allow the user to dismiss or ignore nothing in project data.

7.2 Search, sort, and filters

  • Search by layer, group, zone, or sample display name.
  • Show overlaps only.
  • Show potential collisions only.
  • Show exact key-range stacks.
  • Filter to the current articulation or performance event.
  • Show visible/audible objects only.
  • Sort by authored order, name, key low, root key, velocity low, or diagnostic state.

Authored order remains the default. A temporary sort does not rewrite display order unless the user invokes an explicit reorder command.

8. Selection Model

Structure distinguishes the primary selection from the edit selection. The most recently selected object is primary and determines inspector type and hierarchy focus. All selected objects of that type form the edit selection.

  • A selection contains layers, groups, or zones, never a mixture of types.
  • Standard Ctrl/Cmd and Shift selection conventions apply within a column.
  • The inspector header always states the scope, such as “7 Zones” or “3 Groups.”
  • Selecting a different entity type clears the previous edit selection.
  • When several parents are selected, the child column may show their combined children grouped beneath parent headings.
  • The primary parent's children remain the fallback if a combined child view is deferred from the first release.

9. Context-Sensitive Inspector

The inspector occupies the same right-hand location in Map and Structure modes. It has a sticky header, a scrollable body of compact sections, and stable visual structure across entity types. The header shows entity type, name or selection count, hierarchy path, audition action where applicable, and an overflow menu.

9.1 Layer inspector

  • Name and authored order
  • Workspace visibility
  • Gain and pan
  • Routing bus
  • Audition anchor group
  • Crossfade source, low/high range, direction, and curve
  • Group and zone counts
  • Read-only effective routing and mix summary

9.2 Group inspector

  • Name and authored order
  • Parent layer, including multi-group reassignment
  • Workspace visibility
  • Gain and pan
  • Routing bus
  • Audition anchor zone
  • Round-robin enablement and mode
  • Zone count
  • Read-only effective routing and mix summary

9.3 Zone inspector

  • Sample identity, group membership, and articulation
  • Root key, key range, velocity range, and velocity crossfade
  • Gain, pan, fine tuning, and velocity tracking
  • Release seconds, release shape, and trigger mode
  • Performance event and pitch behavior
  • Round-robin membership
  • Choke group and choke release
  • Controller conditions and damper behavior
  • Playback region, loop behavior, and waveform actions
  • Read-only effective layer/group/zone composition summary

9.4 Mixed values and batch edits

  • Identical values are displayed normally.
  • Different values display as Mixed; no arbitrary selected object supplies the visible value.
  • Entering a value sets that property absolutely on all selected objects.
  • Nudge controls may apply a relative delta while preserving differences.
  • Unsupported combinations remain visible but disabled with a concise reason.
  • One completed control gesture produces one document transaction and one undo step.
  • Validation occurs before commit; partial application is not permitted.

10. Editing and Organization Commands

  • Create, duplicate, rename, reorder, and delete at each appropriate hierarchy level.
  • Move groups between layers using the Group inspector's parent control.
  • Move zones between groups using the Zone inspector's group control.
  • Support drag reorder within a column after the basic command path is established.
  • Support drag reassignment only when the target and resulting parent are unambiguous.
  • Provide Reveal in Map, Open Waveform, and audition commands for zones.
  • Provide select-all-children and select-visible-children commands on layers and groups.

Delete commands must follow the existing document rules. For example, a non-empty group cannot be deleted unless the session contract provides an explicit reassignment or cascading operation.

11. Map and Structure Synchronization

  • A zone selected in Map is selected and revealed in Structure.
  • A group or layer selected in Structure becomes the active authoring context used by creation and assignment commands.
  • Zone multi-selection is preserved when switching views.
  • Returning to Map emphasizes or scopes the active layer/group without silently changing workspace visibility.
  • Map zoom/pan and Structure column/scroll state are remembered independently.
  • Changes made in either view refresh the other from the same session/project state.

The Map and Structure viewers must not maintain separate authoritative selections. A shared typed selection model should drive both, while each viewer may retain non-authoritative presentation state.

12. Keyboard and Accessibility

  • Up/Down moves among rows in the focused column.
  • Right Arrow enters the child column; Left Arrow returns to the parent column.
  • Home/End and Page Up/Page Down follow standard list behavior.
  • Shift extends selection and Ctrl/Cmd toggles selection.
  • Enter invokes the row's default open/reveal action; audition uses an explicit documented command.
  • Every visual diagnostic also has text, an accessible name, and an accessible description.
  • Group tint is supplementary; names, hierarchy, badges, and selection states remain authoritative.
  • Focus remains in a predictable column after refresh, reorder, reassignment, or view switching.
  • Collapsed narrow-width columns expose their full path through accessible breadcrumb controls.

13. Performance and Scale

  • Use virtualized lists and recycled row presentation for groups and zones.
  • Compute aggregate coverage and overlap classifications when topology or relevant fields change, not during paint.
  • Cache normalized key-range geometry independently from viewport pixels.
  • Filter and sort immutable lightweight view models rather than copying full project objects into UI rows.
  • Preserve selection by stable object ID across filtering, sorting, and row recycling.
  • Keep diagnostic analysis off the audio thread and avoid blocking preview or document transactions.

14. Workspace State

The following are presentation preferences and should not alter the authored instrument:

  • Map or Structure mode
  • Column widths, collapsed columns, and scroll positions
  • Active search, sort, and diagnostic filters
  • Expanded stack/relationship groups
  • Inspector section expansion

Authored selection context such as selectedLayerId, project visibility fields, object order, parent membership, and edited property values continue to use the existing session and project contracts.

15. Terminology

Layer now has one precise meaning: the authored parent of a group. Existing UI that uses “Layer Stack” for a set of zones divided by velocity should be renamed Velocity Stack to avoid confusing a zone relationship with the Instrument → Layer → Group → Zone hierarchy.

16. Suggested Delivery

Phase 1 — Navigation foundation

  • Add the Map | Structure switch and workspace persistence.
  • Add virtualized Layers, Groups, and Zones columns.
  • Share typed selection with Map.
  • Add basic layer, group, and zone context inspectors.
  • Add the shared key ruler and one aligned key-range bar per zone.

Phase 2 — Batch editing and organization

  • Add mixed-value presentation and atomic multi-object edits.
  • Add group/layer reassignment, explicit reorder commands, and creation commands.
  • Add search, temporary sorting, and visibility/articulation filters.
  • Add Reveal in Map, Reveal in Structure, Open Waveform, and audition actions.

Phase 3 — Relationship diagnostics

  • Add velocity-stack and round-robin grouping.
  • Add potential-collision and exact-duplicate classification.
  • Add overlap-focused filters and explanatory diagnostic details.
  • Add combined child views for multi-selected parents if user testing supports them.

Phase 4 — Live playback feedback

  • Highlight zones matching incoming MIDI key and velocity.
  • Distinguish the triggered zone from zones rejected by articulation, controller, event, or RR state.
  • Keep live feedback observational; it must not mutate selection or project data.

17. Acceptance Criteria for the Initial Release

  • The user can switch between Map and Structure without losing zone selection.
  • The user can reach any zone through its layer and group without opening a modal dialog.
  • Zones with identical key ranges remain separately visible and selectable.
  • Selecting a layer, group, or zone displays the correct inspector type.
  • Same-type multi-selection presents shared and mixed values correctly.
  • A valid batch edit is atomic and produces one undo step.
  • Keyboard-only navigation can traverse all three hierarchy columns and enter the inspector.
  • Filtering or sorting does not mutate authored order or lose stable-ID selection.
  • The viewer remains responsive with a production-scale instrument and does no work on the audio thread.

18. Open Design Decisions

  • Whether multi-selected parents initially show combined children or only the primary parent's children.
  • Whether the Zone column uses one velocity track per row or a compact numeric field in the first release.
  • Which inspector sections remain shared between Map and Structure and which are Structure-only.
  • Whether drag reassignment is valuable enough to add beyond the safer explicit parent controls.
  • Whether overlap diagnostics should be scoped to one group, one layer, or the entire instrument by default.
  • Which shortcuts can be offered safely across standalone and plugin hosts.
