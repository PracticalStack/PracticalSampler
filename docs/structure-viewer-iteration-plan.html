01 | Product frame

Goal and scope

Creator outcome

A creator can move through layers, groups, and zones without losing the hierarchy path; compare zones that occupy the same ranges; select one or many peers; and edit all compatible attributes from one stable inspector.

Engineering outcome

Map and Structure consume one typed stable-ID selection, one hierarchy projection, and existing document transactions. Presentation state remains outside authored project data, and no UI component invents a second parent-membership model.

Explicit non-goals

This iteration does not change project schema, runtime routing or audio behavior, replace the Zone Map, add live MIDI rejection diagnostics, or make overlap classifications authoritative validation errors.

Design source

Historical implementation record: this plan documents the completed first Structure Viewer iteration. The canonical Unified Instrument Workspace High-Level Design supersedes its separate-view, three-column layout, and inspector-placement decisions while retaining the typed-selection, hierarchy-projection, transaction, diagnostics, and workspace-state foundations delivered here.

02 | Ground truth

Current baseline to extend

Practical Sampler already has the complete authored hierarchy and most required transactions. Layers and groups are first-class objects; groups carry layerId; zones carry groupId. AuthoringSession exposes stable-ID selection and hierarchy mutations, while AuthoringPanel currently coordinates separate layer/group lists, ZoneMapCanvas, ZoneMappingEditor, selection summaries, and lower workbench tabs.

Runtime projectStores layers, child-side group membership, child-side zone membership, and object-local properties.
Authoring sessionOwns validated document transactions, selected layer/group/zone context, undo, and redo.
Authoring panelCoordinates Map selection, hierarchy lists, inspector values, preview, and workbench visibility.
Reusable controlsRepeatedStructureList and compact inspector primitives establish list and field conventions.
MapAlready supports dense rendering, stable group tint, multi-zone selection, range editing, zoom, and minimap navigation.

Primary architecture gap

Selection is distributed across selected session objects, list indices, and zoneMapSelectedZoneIds. A second viewer cannot safely synchronize by adding more component-local state; the iteration needs a typed selection coordinator with stable-ID reconciliation.

Primary presentation gap

The Map deliberately overlays equal geometry. Structure needs a virtualized row projection with a shared pitch ruler so equal key ranges are comparable without changing Map rendering or authoring geometry.

Existing seams: RuntimeModel.h, AuthoringSession.h, AuthoringSession.cpp, AuthoringPanel.h, AuthoringPanel.cpp, ZoneMapCanvas.h, ZoneMappingEditor.h, RepeatedStructureList.h, and WorkbenchLayoutState.h.

First-release multi-parent decision

Do not build a combined child union in this iteration. Multi-selected parents remain editable, but Groups or Zones shows only the primary parent's children and states that scope in its column header. This avoids ambiguous navigation while leaving the typed selection model compatible with a future combined view.

04 | Implementation architecture

Components, ownership, and transaction seams

Pure projection layer

StructureViewModels builds lightweight layer, group, and zone rows from the current project and selection. Counts, coverage, diagnostic flags, and parent relationships are derived; no row owns model data.

Selection coordinator

AuthoringStructureSelection owns entity kind, selected IDs, primary ID, and stable-ID reconciliation. AuthoringPanel adapts it to existing session selection and Map zone selection.

View components

StructureViewer coordinates two compact virtualized hierarchy lists and a custom virtualized StructureZoneList with shared key ruler, filtering, and keyboard column traversal.

Inspector host

StructureInspectorHost switches Layer, Group, and existing Zone inspector content without duplicating field logic. Layer/group editors move toward reusable components instead of expanding AuthoringPanel.

Document mutations

All property changes, reorder, membership moves, and object lifecycle actions call AuthoringSession. New multi-object methods validate the complete edit before one commit and one undo record.

Workspace state

WorkbenchLayoutState or a sibling structure-view state stores view mode, column widths, filters, sorts, and scroll anchors. These values never enter RuntimeProjectModel.

Typed selection and hierarchy read models

Create one source for both viewers

Build the non-visual foundation that makes Map and Structure agree about what is selected, what is primary, and which children belong in each column.

  • SV1.1 Implement AuthoringStructureSelection with replace, toggle, range-extension input, set-primary, clear, and stable-ID reconciliation operations.
  • SV1.2 Adapt Map selection state to typed zone selection and adapt primary layer/group/zone changes back to the existing AuthoringSession context without feedback loops.
  • SV1.3 Define immutable layer, group, and zone row view models containing stable ID, parent ID, display order, primary/secondary selection, visibility, counts, range data, routing/RR/event metadata, and accessibility text.
  • SV1.4 Implement pure hierarchy projection using group.layerId and zone.groupId; derive counts and aggregate key coverage without stored reverse-membership lists.
  • SV1.5 Preserve authored order by default and provide stable temporary sort keys that never rewrite displayOrder.
  • SV1.6 Reconcile selection after create, delete, reassignment, filter changes, undo, redo, and project reload; retain the primary object whenever its stable ID remains valid.
  • SV1.7 Add unit coverage for mixed entity rejection, duplicate-ID removal, primary fallback, parent-child scoping, empty layers/groups, hidden objects, temporary sorts, and Map adaptation.

Gate 1

Range presentation, search, and diagnostics

Make equal geometry independently visible

Turn the Zones column into the comparison surface that the Map cannot be, while keeping diagnostic classification pure, conservative, and explainable.

  • SV3.1 Add a shared 128-note ruler and normalized cached key-range geometry to StructureZoneList; show root markers and retain stable group tint as supplementary identity.
  • SV3.2 Add a separate velocity-range track or compact range field per row plus RR position, articulation, performance event, trigger mode, and crossfade badges.
  • SV3.3 Implement StructureOverlapPolicy for exact key-range stacks, key overlap, key+velocity overlap, velocity-stack candidates, RR siblings, and conservative potential collisions.
  • SV3.4 Produce a structured reason for every diagnostic classification, including which mapping, articulation, event, RR, controller, or crossfade fields distinguish the zones.
  • SV3.5 Add search and filters for overlaps, potential collisions, exact key stacks, current articulation, performance event, and visible objects. Filtering must not mutate selection or authored visibility.
  • SV3.6 Add temporary sorts for authored order, name, key low, root, velocity low, and diagnostic state with an explicit indicator when authored order is not displayed.
  • SV3.7 Add tooltips and accessible descriptions for key/velocity ranges, root, badges, diagnostic state, and hidden/filtered results; color alone is never authoritative.
  • SV3.8 Add unit/render tests for normalized geometry, ruler alignment, equal-range row independence, diagnostic false-positive guardrails, filter composition, sort stability, and high-contrast selection.

Gate 3

All zones remain separately visible even when geometry is identical. Search, filters, sorting, and diagnostics are deterministic, explainable, accessible, and do not alter project state.

Context inspectors and atomic editing

Complete the authoring workflow

Move from navigation to production editing: one inspector slot, typed plural contexts, clear mixed values, explicit parent changes, and document-safe batch transactions.

  • SV4.1 Implement StructureInspectorHost with sticky type/count/path header and Layer, Group, Zone, and same-type plural context dispatch.
  • SV4.2 Extract or wrap the existing layer controls into a reusable Layer inspector covering name, order, visibility, gain, pan, routing, audition anchor, crossfade, counts, and effective summary.
  • SV4.3 Extract or wrap the existing group controls into a reusable Group inspector covering name, parent layer, order, visibility, gain, pan, routing, audition anchor, RR, counts, and effective summary.

  • SV4.10 Add transaction/UI tests for shared values, mixed values, absolute edits, relative nudges, invalid batch rejection, one-step undo/redo, parent moves, anchor repair, RR reconciliation, and inspector switching.

08 | Guardrails

Risks and decisions

Competing selection authorities

Do not synchronize component-local selections after the fact. All lists and Map adapters consume the typed stable-ID selection, and refresh reconciliation happens in one coordinator.

AuthoringPanel growth

AuthoringPanel is already a large composition root. New range rendering, diagnostic policy, selection gestures, and inspector layout belong in focused components or pure helpers, not additional monolithic branches.

Mixed-value ambiguity

Never seed a plural field from the primary object and imply it is shared. Every control type needs an explicit mixed state and documented absolute versus relative edit behavior before batch commit is enabled.

Diagnostic overclaiming

Overlap analysis is descriptive and conservative. It must account for articulation, event, controller, RR, and crossfade distinctions and expose its reasoning rather than label every overlap a conflict.

Compact host pressure

Do not solve narrow layouts by hiding the parent path or inspector identity. Collapse ancestor columns to accessible breadcrumb rails and test the minimum supported plugin dimensions.

UI-driven model shortcuts

Counts, coverage, selection, and overlap flags are derived. Parent reassignment and batch edits must use session transactions; no view component writes directly into RuntimeProjectModel.

Implementation order

Land contract tests and typed selection first, then the navigable shell, then range presentation and diagnostics, then inspectors and mutations. This order keeps every later sprint a consumer of stable selection and view models rather than forcing UI behavior to define the contract accidentally.

09 | Completion criteria

Release gate

The Structure Viewer iteration is complete when

  • Map and Structure are peer mapping views with workspace-persisted mode and independent presentation state.
  • The three-column browser exposes the complete Instrument → Layer → Group → Zone hierarchy and remains usable at supported compact sizes.
  • Zones with identical or overlapping geometry remain independently visible, selectable, searchable, and explainable.
  • One typed stable-ID selection drives Map, Structure, hierarchy path, and inspector type without stale indices or feedback loops.
  • Layer, Group, Zone, and plural same-type inspectors present correct shared/mixed values and commit valid batch edits atomically.
  • Creation, lifecycle, reorder, parent reassignment, reveal, preview, and workbench interactions use validated session transactions and preserve undo/redo.
  • Focused selection, navigation, inspector, diagnostics, integration, accessibility, and production-scale qualification evidence passes.
  • Existing layer, group, Zone Map, velocity-crossfade, preview, waveform, routing, plugin, standalone, and responsiveness regressions remain green.
