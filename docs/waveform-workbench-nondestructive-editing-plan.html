SFZ Non-Destructive Region Import and Authoring Plan

This plan makes SFZ non-destructive sample-region semantics first-class Practical Sampler authoring features. Practical Sampler will import SFZ playback boundaries and loop behavior accurately, compile them into its native project and runtime models, and expose them through a responsive Waveform workbench. Creators can then refine the imported instrument, add Practical Sampler DSP, macros, routing, and future native capabilities without modifying or replacing the source audio. This is a one-way conversion and authoring workflow; customer-facing SFZ export is not a product goal.

01 | Product frame

Goal and boundaries

Creator outcome

A creator imports an SFZ instrument, sees its effective playback and loop regions, and can visually refine those same musical semantics as native Practical Sampler authoring data.

Engineering outcome

SFZ offset, end, loop_mode, loop_start, and loop_end resolve into typed, testable project and runtime contracts with an authoring surface and package parity.

Explicit non-goal

This initiative does not export SFZ, crop or overwrite source audio, or constrain native DSP, macros, and routing to what SFZ can represent. Practical Sampler is the destination format.

Core product rule

When SFZ already defines a non-destructive region behavior, Practical Sampler implements that semantic contract first and exposes it in authoring. After import, the value is native Practical Sampler project data and may participate in richer DSP, macro, routing, and package workflows.

One-way conversion rule

The supported path is SFZ → Practical Sampler project → playable Practical Sampler package. SFZ header inheritance must be resolved correctly during import, but source formatting, comments, include layout, and opcode placement do not need to be retained for re-export.

Repository rule

All new work, tests, documentation, and migration logic land in PracticalSampler. Existing drs C++ namespaces and artifact extensions remain unchanged unless a separate naming initiative explicitly replaces them.

Primary architectural gap

A fixed 192-point result is appropriate for a thumbnail, but not for an editor. Enlarging those points would create a misleading waveform and would make zero-crossing and precise boundary work impossible.

03 | Locked decisions

Product and interaction decisions

Included in the committed scope

  • Waveform zoom, horizontal navigation, fit, and overview recovery.
  • Playback start and end handles, with source audio outside the region visibly dimmed.
  • Forward-loop enablement and loop start/end handles.
  • Temporary range selection with commands to set playback or loop region.
  • Selection, playback-region, and loop audition modes.
  • Frame and time readouts, direct numeric entry, keyboard adjustment, and snapping.
  • Exact import of the portable SFZ v1 region subset: offset, end, loop_mode, loop_start, and loop_end.
  • Undo, redo, save/restore, host-state, Preview, Publish, and playable-package parity.

Excluded from this initiative

  • Writing changes into WAV, AIFF, FLAC, or any other source file.
  • Creating cropped or processed derivative audio files.
  • Normalize, reverse, destructive fades, resampling, denoising, or spectral editing.
  • Multitrack, splice, comp, or DAW-style clip editing.
  • Automatic source replacement for zones sharing a sample.
  • Background analysis that starts merely because the editor opens.
  • Customer-facing SFZ export or preservation of SFZ source-file formatting and structure.

Selection is transient

Dragging an arbitrary selection does not dirty the project. Only an explicit command or boundary-handle commit changes the selected zone.

Edits are zone-scoped

Editing one zone does not silently modify sibling zones that reference the same sampleSourceId.

One gesture, one history item

Mouse-down begins a transient edit, dragging updates the local overlay, and mouse-up commits exactly one labeled authoring transaction.

05 | Contracts

SFZ conversion, range, and edit contracts

end=N SFZ's inclusive endpoint converts to internal exclusive sampleEndFrame=N+1. An absent opcode resolves to source end. Playback End handle and numeric field, with SFZ provenance available in import diagnostics.
loop_mode Typed behavior for no_loop, one_shot, loop_continuous, and loop_sustain; compile each value into explicit voice-lifecycle semantics. Loop Mode selector. The existing loopEnabled boolean is an interim compatibility representation, not the final SFZ authoring contract.
loop_start=N Inclusive loop start: loopStartFrame=N. Loop Start handle and numeric field.
loop_end=N SFZ's inclusive endpoint converts to internal exclusive loopEndFrame=N+1. Loop End handle and numeric field.
ContractCanonical ruleCompatibility behavior
Playback range [sampleStartFrame, resolvedSampleEndFrame). The start is inclusive and the end is exclusive. Add sampleEndFrame; value 0 resolves to the source frame count so existing projects retain full-tail playback. SFZ end=0 remains representable because it converts to exclusive value 1.
Loop range [loopStartFrame, loopEndFrame), valid only when loopEnabled and fully contained inside the resolved playback region. Existing disabled-loop values may remain stored, but enabling a loop requires a valid ordered contained range.
Temporary selection A workspace-only half-open frame range associated with the current source identity and zone selection revision. Selection clears when the selected zone or source identity changes; it is not serialized and does not enter undo history.
Boundary normalization All proposed changes pass through one pure normalization/validation function before presentation preview or commit. SFZ import, UI, loader, snapshot, prepared model, package projection, and tests use the same ordering and containment rules.
Edit transaction A completed handle drag or explicit selection command produces one updateSelectedZone action with a stable label. Cancel, lost capture, zone change, editor close, or invalid input restores the pre-gesture presentation and produces no history item.
Source identity Peak and snap results are keyed by sample-source ID, normalized path, size, modification ticks/fingerprint, channel reduction, visible frame range, and level of detail. Stale worker completions are rejected when any identity or request generation differs.

Schema recommendation

Introduce named SFZ-region schema constants rather than scattering literal version checks. The migration should advance the current project/authoring pair, default missing sampleEndFrame to 0, and replace the long-term loop boolean with a typed mode capable of preserving all portable SFZ v1 loop behaviors. Save canonical new-schema documents with explicit native fields; do not retain an editable SFZ document inside the project.

Import findings contract

Every recognized region opcode must be classified as exact, transformed, approximated, or unsupported. Unsupported or partially represented SFZ behavior produces an actionable import finding; it is never silently presented as fully converted.

Loop containment migration

Legacy projects may contain a loop that begins before an authored sample start. Loading must remain deterministic: report the incompatibility and require correction, or migrate only under an explicitly tested rule. Never silently move musical boundaries merely to satisfy the new editor.

Presentation, worker, and audio ownership

Immutable publishAdopt only the newest matching peaks, prepared graph, and serialized state.
Audio renderVoice reads immutable start/end/loop fields with no locks, allocation, disk access, or editor dependency.

Multiresolution waveform strategy

Use a hybrid cache: retain a whole-source overview level, then build fixed-size visible-range tiles at the level of detail required by the current pixels-per-frame ratio. Coarser levels aggregate from finer cached tiles where possible. Deep zoom may request bounded source reads, but it must never decode or retain an entire large source merely to draw a small range.

  • Key tiles by immutable source identity, channel reduction, frame span, and level.
  • Prioritize visible tiles, then one viewport of look-ahead on each side.
  • Keep the last complete compatible view while replacements build.
  • Bound cache memory and evict least-recently-used, unleased tiles off the audio thread.

Gesture and preview strategy

Boundary movement is visually live but transactionally deferred. During drag, the component paints a proposed region from small value types. At commit, the session receives one zone snapshot. Scoped Preview preparation is requested after commit and follows the existing asynchronous latest-request-wins contract.

  • No full project clone, validation, digest, host serialization, or playback wait inside pointer callbacks.
  • Optional audible drag feedback may be added only through a bounded, explicitly qualified preview control path.
  • Until that path exists, commit-time audition is the supported behavior.

SFZ region contract, interaction policy, and baseline fixtures

Conversion semantics first

Lock the portable SFZ v1 region mapping and build pure, testable conversion and edit policy before adding stateful component behavior.

  • WF-1.1 Define the one-way mapping for offset, end, loop_mode, loop_start, and loop_end, including whether each effective value came from SFZ inheritance, an explicit region opcode, WAV metadata, or a native authoring edit.
  • WF-1.2 Add canonical frame-range and viewport value types with explicit half-open semantics. Convert inclusive SFZ end=N and loop_end=N to internal exclusive N+1 exactly once at the import boundary.
  • WF-1.3 Define typed internal loop modes for no_loop, one_shot, loop_continuous, and loop_sustain; treat the existing loop-enabled boolean as an interim compatibility projection, not the final contract.
  • WF-1.4 Implement pure normalization for playback, loop, selection, drag, and legal-boundary constraints, with explicit import findings for unsupported, malformed, or partially represented SFZ behavior.
  • WF-1.5 Define pointer-to-frame and frame-to-pixel transforms with overflow-safe 64-bit math, plus edit gesture state for begin, update, commit, cancel, lost capture, zone change, and source change.
  • WF-1.6 Add deterministic SFZ/WAV fixtures for omitted and explicit opcodes, inheritance, metadata fallback, end=0, one-frame ranges, malformed regions, every portable loop mode, and mono, stereo, multichannel, short, and long sources.
  • WF-1.7 Record current waveform build I/O, paint, selection, Preview dispatch, SFZ projection, and package-loop behavior as a before-change baseline.

Existing waveform, authoring, render, streaming, and package suites remain unchanged and green.

Expected touchpoints: new waveform region policy/view-model files, focused unit tests, baseline artifact under the existing test output convention.

09 | Future iteration

Automated audible-parity testing

Deferred, not a baseline release dependency

Listening comparisons remain the final musical judgment. A later iteration can automate repeatable waveform-output checks around those comparisons, but it must validate the one-way SFZ conversion and native delivery pipeline—not create a hidden SFZ exporter.

Start with analytic fixtures

Generate small synthetic WAV sources whose sample values make offset, end, loop boundaries, and note-off behavior unambiguous. Render each portable loop mode and assert the expected frame sequence exactly.

Compare every native stage

Render the imported model, saved/reopened .drsproj, restored host state, Preview/Publish preparation, and opened playable package from the same MIDI/event script. Compare aligned stereo buffers per sample and retain peak, RMS, checksum, and first/last-nonzero summaries.

Add curated reference-player renders

For a small licensed fixture set, capture 32-bit float WAV output from a trusted SFZ player and compare it with Practical Sampler using deterministic event timing, latency alignment, null/difference energy, RMS/SNR, spectral, and envelope tolerances. Use this as compatibility evidence, not as proof that every implementation must null exactly.

Make failures listenable

Emit expected.wav, actual.wav, difference.wav, comparison.json, and compact waveform/spectral images so a failed automation check can immediately become a focused listening comparison.

Existing foundation

tests/support/Sprint4OfflineRenderHarness.* already retains stereo samples, compares them at a 1.0e-6 tolerance, and records peak, RMS, checksum, and first/last-nonzero evidence. The next iteration should extend that harness with reusable WAV artifact output, alignment/tolerance profiles, and SFZ-region fixture orchestration rather than replace it.

10 | Risk control

Risks and guardrails

Schema breadth

sampleEndFrame touches more than the visible editor. Missing one equality, digest, snapshot, prepared, package, or host-state seam can create a UI that appears correct but plays or recalls incorrectly.

Control: land the field as a dedicated end-to-end phase with compile-time and round-trip coverage before exposing playback-region commands.

Gesture-driven preparation churn

Calling the existing project edit and preparation path for every pointer move would recreate the responsiveness problems already removed from authoring.

Control: local transient overlay during drag, one commit at gesture end, coalesced background Preview afterward.

Misleading zoom detail

Scaling cached overview peaks can imply precision that the data does not contain.

Control: visible-range level-of-detail identity, partial/loading presentation, and no boundary snapping against coarse display buckets.

Streaming boundary reads

An exclusive playback end changes interpolation and page look-ahead behavior. A naive stop check can read beyond the region or truncate the final valid interpolation.

Control: explicit boundary interpolation tests for resident and paged sources at multiple pitch ratios.

Package/editor divergence

The current package projection does not preserve loops. Shipping richer authoring without delivery parity would create creator-visible data loss.

Control: package export/open/render parity is a release gate, and the existing rejection is removed only after preservation is proven.

SFZ semantics flattened incorrectly

Resolving inheritance, WAV metadata fallback, inclusive ends, or loop modes incorrectly can produce a plausible-looking native region that does not sound like the source instrument.

Control: resolve effective values before projection, convert boundaries once, retain value provenance for diagnostics, and emit findings instead of silently claiming complete support.

Feature creep into destructive editing

Selection terminology can quickly turn into requests for crop, fade, normalize, or file replacement.

Control: commands are named Set Playback Region and Set Loop, never Crop or Trim File. Source integrity tests remain mandatory.

Primary engineering guardrail

Do not redesign the qualified streaming, asynchronous Preview/Publish, or background host-state publication architectures to implement this editor. Extend their immutable request/result contracts and preserve their ownership rules.

Release gates and delivery sequence

Mandatory release gates

  • Must The source file hash, size, and modification time never change.
  • Must A completed gesture creates exactly one undoable selected-zone edit; canceled gestures create none.
  • Must Existing projects without sampleEndFrame retain full-tail playback.
  • Must The supported SFZ v1 region subset resolves inheritance and WAV metadata precedence correctly, converts inclusive ends exactly once, preserves all four loop modes, and emits findings for unsupported or partial behavior.
  • Must Playback and loop regions are sample-accurate and identical across resident, streaming, offline, Preview, and published playback.
  • Must Playable-package export/open preserves all supported region and loop fields.
  • Must Ordinary waveform input, paint, and tab refresh stay within one 60 Hz frame on the reference system.
  • Must The message thread performs no sample reads, full project validation, full serialization, preparation waits, or polling.
  • Must The audio thread performs no allocation, lock acquisition, file I/O, or editor-state access.
  • Must Rapid selection, zoom, snap, and Preview churn publish only the newest eligible result.
  • Must Keyboard and assistive-technology users can reach and edit every boundary exposed to pointer users.

Deferrable enhancements

  • Later Transient detection and transient snapping.
  • Later Loop crossfade and crossfade visualization.
  • Later SFZ v2 and implementation-specific region features beyond the portable v1 baseline, including alternate/reverse loop types, finite loop counts, and modulated offsets.
  • Later Stereo split-lane waveform presentation.
  • Later Batch application of one region to multiple selected zones.

Deferrable enhancements must not weaken file immutability, interoperability, or real-time gates when they are later activated.
