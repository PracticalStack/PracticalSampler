01 | Product frame

Goal and scope

Creator outcome

An SFZ zone with a loop point before its authored playback start imports successfully and plays the intended attack, then loops without changing the source sample.

Engineering outcome

The importer, project model, compiler, prepared playback, render model, voice, persistence, and package paths agree on the relaxed loop invariant.

Explicit non-goal

This iteration does not reinterpret offset, move playback start automatically to loop_start, add new SFZ loop modes, or edit source audio.

Scope boundary

All implementation, tests, fixtures, and this plan belong to PracticalSampler/. The sibling _analysis/Rhapsody/ tree is excluded.

02 | Ground truth

Current failure and cause

Practical Sampler currently treats the loop as required to be fully contained by the zone's playback range. The SFZ contract rejects a resolved loop when loop_start < playbackStart or loop_end > playbackEnd.

Current required invariant:
playbackStart <= loopStart < loopEnd <= playbackEnd

Soft String Spurs contains valid-looking authored cases where offset is later than loop_start. For example, a Swells region uses offset=30767 and loop_start=30549. The importer therefore reports The resolved loop must be fully contained by the resolved playback range before a playable project is created.

Not the problem

  • loop_mode=loop_continuous is already parsed and mapped.
  • Loop start/end are already represented as zone fields.
  • Normal loops whose start is at or after playback start must continue to work unchanged.

The actual gap

  • Import validation rejects the earlier loop start.
  • Several downstream validators repeat the same restriction.
  • SamplerVoice also requires the loop start to be at or after playback start.

Reference seams: SFZ contract validation, runtime compiler validation, and voice loop activation.

03 | Locked behavior

Playback semantics for this iteration

Note-onVoice position begins at the authored zone playbackStart / SFZ offset.
Initial passAudio advances normally, even if loop_start is earlier than the initial position.
Loop endWhen playback reaches loop_end, the loop becomes active.
Backward wrapPosition jumps to the authored earlier loop_start.
Steady stateloop_continuous keeps wrapping; loop_sustain stops wrapping on note-off.
New active-loop invariant:
loopStart < loopEnd
loopStart <= playbackStart < loopEnd
loopEnd <= playbackEnd

Preserve offset

Do not move playbackStart backward to loop_start. The attack and timing encoded by the SFZ remain authoritative.

Keep half-open frames

Continue using native [start, end) ranges. Only the containment relationship changes; inclusive SFZ endpoint conversion does not.

Keep mode behavior

loop_continuous wraps through release. loop_sustain stops wrapping at note-off and plays the tail.

07 | Risk control

Risks and guardrails

Risk: invalid content becomes playable

Relaxing the lower bound must not accept collapsed ranges, loop ends before note-on position, or loop ends beyond playback end. Keep explicit ordered and enterable-range checks in every layer.

Risk: attack timing changes

Normalizing playback start to loop start would alter the instrument. Preserve the authored playback start and only change the first-wrap destination.

Risk: one validator is missed

Use a repository audit for loopStartFrame < sampleStartFrame and run clean load, prepare, render, package, and host-state paths.

Risk: page preparation misses the loop head

Keep loop-head prewarm independent from playback-start prewarm and exercise the first wrap under a page-miss test.

Compatibility guardrail

Existing projects and zones with loops fully inside playback must serialize identically and render identically. The only new accepted relationship is an earlier loop start that still permits the voice to enter the loop before playback reaches its end.

08 | Completion

Release gate

Iteration is complete when

  • Soft String Spurs imports without the reported earlier-loop-start projection errors.
  • The native zone preserves the authored playback start and earlier loop start.
  • loop_continuous wraps at runtime after the initial playback position reaches loop_end.
  • loop_sustain retains its existing note-off behavior.
  • All project, prepared, package, host-state, and render-model paths accept and preserve the range.
  • Invalid and non-enterable ranges remain rejected with stable diagnostics.
  • Targeted and full Practical Sampler tests pass from a clean checkout.

Definition of done

The feature is not complete when only the importer accepts the SFZ. It is complete when the accepted zone survives native persistence and package projection and produces the intended first backward loop wrap in the actual voice/render path.
