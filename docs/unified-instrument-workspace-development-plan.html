01 | Product frame

Goal and scope

Creator outcome

A creator can navigate the complete hierarchy, understand the active path, edit the selected object or compatible multi-selection, and ask the existing Map to show exactly the relevant zones without leaving the workspace.

Engineering outcome

One stable-ID selection drives inspector context; a separate stable-ID scope drives Map membership; a third workspace flag drives Map visibility. All authored edits continue through validated AuthoringSession transactions.

Explicit non-goals

No audio-engine behavior, project schema, mapping geometry, Zone Map renderer, lower-workbench content, cross-type batch editing, or authored visibility semantics change in this iteration.

Source of truth

The product contract and visual behavior are defined by the Unified Instrument Workspace High-Level Design. The older Structure Viewer iteration plan is historical implementation evidence only where its separate mode switch and three-column presentation conflict with the new HLD.

  • UIW0.3 Record current compact/expanded bounds from AuthoringPanel::resized(), including lower-workbench open/closed states and the existing Map/Structure toggle geometry.
  • UIW0.4 Extend StructureViewerFixtures with an empty instrument, empty layer/group, same-group stacks, same-layer multi-group zones, cross-layer multi-selection, hidden containers, and missing-parent repair cases.
  • UIW0.5 Capture baseline message-thread timings and component snapshots at 820×700, 1120×800, and a 1,700-zone production fixture.
  • UIW0.6 Add new CTest targets drs.unified_workspace.contract, drs.unified_workspace.ui, and drs.unified_workspace.qualification; keep existing drs.structure_viewer.* targets until the retirement gate.

Gate 0

1

Independent workspace state and scope policy

Separate what is selected, shown, and visible

Create the non-visual state model that every later phase consumes.

  • UIW1.1 Add instrument to StructureSelectionKind; define root selection behavior without adding a selected-instrument field to the authored project.
  • UIW1.2 Implement StructureScope with kinds instrument/layer/group, stable ID, equality, validation, and deterministic instrument-root fallback.
  • UIW1.3 Implement pure deriveStructureScope(project, selection): layer → layer; group → group; one zone → parent group; same-group zones → group; same-layer zones → layer; otherwise instrument.
  • UIW1.4 Implement scope reconciliation after delete, reparent, import, reload, undo, and redo; prefer the nearest valid ancestor and never select an arbitrary sibling.
  • UIW1.5 Evolve StructureViewState: add mapPaneVisible, active StructureScope, tree width, disclosure IDs, and tree scroll anchor; retain search/filter/sort values.
  • UIW1.6 Add workspace snapshot round-trip tests and assert that visibility, scope, disclosure, width, search, and Map view state never enter serialized project JSON.
  • UIW1.7 Add ScopedZoneProjection tests for instrument/layer/group membership, hidden-container policy, selected-zone emphasis, filter composition, stable authored order, and empty results.

Gate 1

Tests can independently change selection, scope, and Map visibility; scope derivation is deterministic for every supported selection shape and remains workspace-only.

  • UIW2.2 Build InstrumentStructureBrowser on a virtual ListBox; render only visible flattened rows and keep collapse state by stable ID.
  • UIW2.3 Implement pointer, Ctrl/Cmd toggle, Shift range selection among same-type visible peers, double-click disclosure, and deterministic primary selection.
  • UIW2.4 Implement Up/Down traversal, Left/Right collapse/parent/first-child behavior, Enter selection, type-ahead/search focus, and focus restoration after refresh.
  • UIW2.5 Add hierarchy action bar commands for New Layer, New Group, New Zone/import, Duplicate, Delete, and More; reuse existing session transactions and disable invalid contexts with reasons.
  • UIW2.6 Reuse existing search, visibility, articulation/event, overlap, and diagnostic projections without allowing filters to delete selection or authored objects.
  • UIW2.7 Add Show Zones to the action bar and row context menu as an intent only; Phase 4 supplies the command implementation.

Gate 3

The old view switch is gone. Show Map changes layout only, the browser and inspector remain authoritative, and the current Zone Map still passes every characterized interaction.

4

Show Zones and scoped Map projection

Connect hierarchy intent to the existing Map

Implement the command that makes the unified workspace useful without coupling scope back to ordinary selection.

  • UIW4.1 Add one showZonesForCurrentSelection() coordinator path; all inspector, tree action bar, context-menu, and keyboard invocations call this path.
  • UIW4.2 Derive and commit StructureScope, set Map visible when needed, build the scoped zone projection, call ZoneMapCanvas::setZoneSummaries(), then fit the projected content.
  • UIW4.3 Add a public fitAllVisible()/fitScope() seam to ZoneMapCanvas; do not reach into private viewport math from AuthoringPanel.
  • UIW4.4 Replace buildVisibleZoneSummaries() with the tested ScopedZoneProjection; retain authored visibility exceptions for selected zones only where the HLD requires them.
  • UIW4.5 Add the toolbar summary “Showing zones: {scope name} · {count}” plus an accessible scope kind/path; expose Fit Scope and filter state without turning the summary into selection.
  • UIW4.6 Preserve Layer or Group inspector context after Show Zones. Only a subsequent Zone Map click changes selection and dispatches the Zone inspector.
  • UIW4.7 When one or many zones invoke Show Zones, reveal selected zones inside the derived parent/common-ancestor scope without hiding siblings.
  • UIW4.8 Reconcile scope and selection independently on reparent/delete/undo/reload; prevent callback loops among session selection, tree selection, Map selection, and refresh.
  • UIW4.9 Add contract/integration tests for every selection-to-scope row in the HLD, Map-hidden invocation, repeated invocation, empty scope, filters, and unchanged document/undo state.

Gate 4

Show Zones produces the exact instrument/layer/group/common-ancestor zone set, opens and fits the existing Map, and preserves the invoking selection and inspector.

5

Inspector completion and overlap access

Finish the production authoring workflow

Consolidate editable inspectors and ensure intentional Map overlap never makes a zone unreachable.

  • UIW5.1 Promote StructureInspectorHost from alias to explicit host dispatch; reuse current Layer/Group snapshots and ZoneMappingEditor callbacks rather than duplicating fields.
  • UIW5.2 Add Show Zones as the primary contextual action for instrument/layer/group/zone/plural-zone contexts; retain Audition, Open Waveform, Select Children, Duplicate, and overflow actions as applicable.
  • UIW5.3 Verify every multi-select-compatible Layer, Group, and Zone field reports shared/mixed state and commits one atomic patch with one undo record.
  • UIW5.4 Implement wide two-column inspector layout when Map is hidden and the compact drawer variant when the shell cannot preserve useful tree/Map/inspector widths.
  • UIW5.5 Build ZoneMapOverlapIndex from cached visible geometry; identify exact and substantially occluded candidates without changing paint order.
  • UIW5.6 Add a count-backed stack affordance and native chooser showing zone name, key/velocity, RR, articulation, and event; selecting a candidate changes zone selection only.
  • UIW5.7 Add Next/Previous Zone-in-Stack keyboard commands, focus announcements, tree reveal, and inspector synchronization.
  • UIW5.8 Add transaction and UI tests for inspector dispatch, mixed values, Show Zones placement, overlap chooser ordering, coincident hit access, focus, and unchanged scope.

Gate 5

Every hierarchy context has a real editable inspector, Show Zones is consistently available, and every coincident Map zone is independently reachable by pointer and keyboard.

07 | Guardrails

Risks and mitigations

Selection–scope recoupling

Do not filter Map input in tree selection callbacks. Only the Show Zones coordinator may commit scope; tests assert the Map vector is unchanged by selection alone.

AuthoringPanel growth

Keep scope derivation, projection, tree flattening, overlap indexing, and layout math in focused helpers. AuthoringPanel composes and routes intents.

Map regression

Change Map input and add narrow public seams only. Avoid renderer rewrites, new coordinate systems, or duplicated selection state.

Workspace-state migration

Read old snapshots defensively, map old Map mode to Map visible, discard obsolete column widths, and never publish presentation state into the document.

Compact-shell pressure

Enforce minimum useful Map and tree sizes, then use the specified inspector drawer/full-inspector state. Do not solve pressure by clipping controls or restoring three columns.

Premature deletion

Keep the old Structure viewer and tests until the persistent tree, selection, inspector, and Show Zones paths reach parity. Remove them in one final cleanup phase.

Sequencing rule

Do not begin shell surgery before Phase 1 state contracts pass. Do not remove the old viewer before Phase 5 completes. Do not optimize projection by changing audio/runtime ownership; all performance work remains UI-side and cache-based.

08 | Completion criteria

Release gate

The Unified Instrument Workspace is complete when

  • No Map | Structure mode switch or three-column Structure Viewer remains in production.
  • The Instrument Structure browser is persistent across every workbench tab.
  • Selection, Map scope, and Map visibility remain independent, workspace-only, stable-ID state.
  • Show Map changes layout only and restores prior Map state.
  • Show Zones derives the specified scope, opens/fits the existing Map, and preserves inspector context.
  • The existing Zone Map retains dense rendering, minimap, selection, editing, audition, and navigation behavior.
  • Layer, Group, Zone, and compatible plural inspectors are editable, accurate, atomic, and undoable.
  • Every coincident zone is reachable through the tree and Map stack access.
  • 820×700 and 1120×800 layouts preserve useful Map, tree, inspector, and workbench surfaces.
  • Keyboard and screen-reader users can distinguish selection, scope, visibility, and commands.
  • 1,700-zone responsiveness remains inside the established message-thread budget.
  • Standalone and VST3 builds plus focused and regression suites pass from a clean checkout.
