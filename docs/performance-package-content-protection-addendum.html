Reviewed Baseline

The protected package product path and irreversible V3 engineering cutover are complete. Release remains gated by production credential provisioning and independent security approval.

Current boundary: normal exports emit only verified signed V3, and every product activation entry point now requires a runtime decrypt-key provider plus immutable publisher trust. Missing production provisioning fails closed without a V1/V2 fallback or replacement of last-known-good playback.
  • Available: hash-pinned libsodium, XChaCha20-Poly1305, Ed25519/Ed25519ph adapters, random content keys/nonces, canonical binary AAD, signed/enveloped V3 serialization, strict structural parsing, bounded file-backed signature verification and record decryption, versioned release-key policy/provider, immutable publisher trust store, isolated controlled signer, move-only zeroized secret buffers, semantic SHA-256, and focused negative tests.
  • Missing: production key/service provisioning and named owners, plus independent security review and release approval.
  • Current validation: the focused crypto, V3 reader/writer/export/activation, adversarial smoke, release-gate, Accurate Salamander V3 qualification, complete 229-test repository matrix, and 100-cycle lifecycle stress pass in supported Windows x64 Release. A clean Debug build also passes the complete matrix and stress workload after the retained cold-first-launch host observation documented in the Phase 7 evidence.

1

Freeze the Real V3 Byte Format

Complete

Replace the prototype framing with the byte-exact format promised by the parent plan.

Development tasks

  • CPCA-1-T1 Serialize the wrapped content key, encryption-key ID, signing-key ID, signature suite, signature, bounded TOC, and record offsets.
  • CPCA-1-T2 Replace delimiter-joined AAD with a versioned, length-prefixed binary encoding for every authenticated field.
  • CPCA-1-T3 Define signature coverage over the complete canonical envelope, TOC, record ordering, identities, nonces, ciphertext, and tags.
  • CPCA-1-T4 Reject duplicate identities, invalid ordering, empty identities, unknown suites, unsupported versions, overflow, truncation, and trailing bytes.
  • CPCA-1-T5 Replace the FNV plaintext digest with SHA-256 over canonical semantic records, including identities and boundaries.

Validation

  • Publish golden byte-layout and AAD vectors.
  • Prove delimiter/field-boundary ambiguity is impossible.
  • Mutate every header, envelope, TOC, identity, ordering, size, nonce, ciphertext, tag, and signature field.
  • Round-trip empty, maximum-size, multi-page, and multi-generation records.
Primary code: PackageV3.*, PackageKeyEnvelope.*, PackageSignature.*, format specification, golden fixtures.
Implementation evidence: canonical AAD golden vector, structural bounds and ordering cases, signed header/envelope/TOC/payload mutation cases, and a complete one-bit-per-byte package mutation sweep pass in drs.package_v3. The focused V1/V2 compatibility and package-protection tests also remain green.

Exit gate

One canonical serialization exists; no ambiguous AAD or unsigned mutable field remains; golden vectors and the complete mutation matrix pass.

2

Build the Bounded, Signature-First Reader

Complete

Make V3 a hostile-file boundary that never reads the whole package or publishes unauthenticated plaintext.

Development tasks

  • CPCA-2-T1 Parse only a fixed-size header and bounded envelope/TOC ranges from the file.
  • CPCA-2-T2 Verify publisher signature and all bounds before trusting package-owned structure.
  • CPCA-2-T3 Resolve and unwrap the content key only after signature validation.
  • CPCA-2-T4 Provide blocking worker-side APIs that independently decrypt metadata, heads, and requested sample pages without resident package loading.
  • CPCA-2-T5 Use checked offset arithmetic and explicit package, header, TOC, record, and allocation ceilings.

Validation

  • Exercise sparse, oversized, truncated, reordered, duplicate, and adversarial-length files.
  • Measure bytes read for metadata, heads, one page, and unrelated records.
  • Prove signature/AEAD failure returns no plaintext and leaves last-known-good playback unchanged.
  • Audit thread use: no crypto, allocation, seek, or file operation on the audio thread.
Primary code: PackageReaderDispatch.cpp, PackageV3FileReader.*, PackageV3.*, PackageSignature.*, and PackageV3FileReaderTests.cpp.
Implementation evidence: drs.package_v3.file_reader verifies the full signed region through Ed25519ph with a 64 KiB payload buffer, retains no payload ciphertext, reads only a requested record for AEAD open, and rejects unknown/revoked/wrong signing keys, wrong content/release keys, mutation, truncation, reordered/duplicate TOCs, adversarial lengths, and oversized declared sections without returning plaintext. Unkeyed dispatch now reads only the eight-byte format signature.

Exit gate

Reader memory is bounded independently of package size; signature verification precedes acceptance; requested records/pages open without resident package loading.

Operationalize Release Keys and Publisher Signing

Provisioning required

Turn helper APIs into an auditable key lifecycle without placing production secrets in desktop code.

Development tasks

  • CPCA-3-T1 Implement the concrete runtime PackageKeyProvider and versioned release-key lookup.
  • CPCA-3-T2 Embed a read-only public trust store with activation, retirement, and revocation metadata.
  • CPCA-3-T3 Build controlled CI/service signing that accepts canonical package bytes and returns an Ed25519ph signature.
  • CPCA-3-T4 Keep private signing material and release keys out of source, desktop binaries, fixtures, logs, symbols, crash reports, and artifacts.
  • CPCA-3-T5 Use move-only sensitive buffers and dependable zeroization such as sodium_memzero throughout key paths.

Validation

  • Exercise signing-key and release-key rotation, retirement, unknown-key, revoked-key, and outage scenarios.
  • Demonstrate that disclosure of a symmetric test key cannot create a publisher-valid modified package.
  • Scan repositories, binaries, symbols, logs, artifacts, and fixtures for secret leakage.
  • Prove an unauthorized desktop build cannot invoke production signing.
Primary code: PackageKeys.*, PackagePublisherTrustStore.*, PackagePublisherSigning.h, SecureBuffer.*, tools/package_signer, and PackageKeyLifecycleTests.cpp. Operations: key operations runbook.
Implementation evidence: drs.package_keys.lifecycle covers active/retired/revoked/unknown key behavior, release-key and audit-service outages, signing-key rotation, symmetric-key disclosure with failed publisher trust, canonical-input enforcement, immutable public-only trust configuration, signer target isolation, and sodium_memzero use. The opt-in controlled signing executable also builds successfully.
External exit-gate work: assign release-engineering/security owners; provision managed signing and release-key storage; inject real public trust entries; restrict production signing identity; and execute the rotation/recovery drill in the linked runbook. No production secret was created or embedded during this implementation.

Exit gate

The production publishing path is operational and auditable; shipped applications contain no private signing key; rotation and recovery are demonstrated.

Connect Production Export to V3

Provisioning required

Make the existing playable-instrument record plan produce a complete signed V3 package.

Development tasks

  • CPCA-4-T1 Map manifest, runtime settings, UI definitions, artwork, license, stream metadata, sample heads, and sample pages into V3 records.
  • CPCA-4-T2 Strip source paths, original WAV names/chunks, authoring-only state, and unnecessary metadata before encryption.
  • CPCA-4-T3 Generate one random content key per export and unique random nonces per record.
  • CPCA-4-T4 Wrap the content key, request publisher signing, verify selected records, and atomically publish the final file.
  • CPCA-4-T5 Preserve cancellation, progress reporting, staging cleanup, and sensitive-key retirement on every exit path.

Validation

  • Export a real project twice: encrypted bytes differ while semantic digest and rendered playback match.
  • Search package and staging bytes for JSON labels, paths, filenames, image signatures, WAV markers, and planted PCM canaries.
  • Force cancellation and failures at every stage; require no partial publication or plaintext residue.
  • Reopen and verify the completed package before reporting export success.
Primary code: PerformancePackageExportService.cpp, V3 streaming writer, compiler/sanitizer, export lifecycle tests.
Implementation evidence: drs.package_v3.streaming_export and drs.performance_package.v3_production_export prove bounded record-at-a-time AEAD, fresh keys/nonces, stable semantic digests, protected-plaintext scans, file-backed controlled signing, staged signature/selected-record verification, cancellation cleanup, last-published-file preservation, asynchronous workflow injection, and fail-closed behavior with no deterministic/V2 writer reference in the production export service. The focused eight-test security/export matrix passes.

Exit gate

Engineering implementation complete; production provisioning required. Once CPCA-3 supplies the real active release-key provider, signing service, public trust entry, owners, and audited credentials, the normal Export Playable Instrument workflow produces a verified signed V3 file and never invokes the deterministic provider. Without those dependencies it publishes nothing. The resulting V3 file is consumed by the authenticated CPCA-5 activation path.

Complete Adversarial and Performance Qualification

Complete

Expand the focused smoke tests into reproducible evidence for every security and real-time invariant.

Development tasks

  • CPCA-6-T1 Add official AEAD and Ed25519ph vectors plus a one-million-nonce production-RNG test.
  • CPCA-6-T2 Build complete positive/negative fixture generators and coverage-guided parser, envelope, signature, framing, and AAD fuzz targets.
  • CPCA-6-T3 Add automated plaintext scans across packages, staging/temp directories, logs, host state, and crash artifacts.
  • CPCA-6-T4 Run Accurate Salamander export/load/page/playback benchmarks against the frozen V2 and project baselines.
  • CPCA-6-T5 Run Debug/Release on supported Windows x64, MSVC static analysis, and Clang sanitizer/fuzzer targets where the toolchain is available.

Validation

  • CPCA-6-V1 Require zero crash, overflow, unbounded-allocation, unauthenticated-plaintext, nonce-reuse, and signature-bypass findings.
  • CPCA-6-V2 Measure package overhead, metadata open, head readiness, page latency, first note, working set, cancellation, and sustained playback.
  • CPCA-6-V3 Perform archive/hex inspection, record carving, key-string scans, and attempted repacking.
  • CPCA-6-V4 Produce machine-readable release-gate evidence tied to the traceability matrix.
Implementation evidence: official XChaCha20-Poly1305 and RFC 8032 Ed25519ph vectors pass; 1,000,000 production nonces contain zero duplicates; the complete valid-package byte-mutation matrix and 100,000-case arbitrary-input smoke pass in Debug and Release; five Clang/libFuzzer targets are available for parser, framing, signature, envelope, and AAD coverage. Persistent-artifact and 2.62 GB package scans found no protected canaries, and repacking failed publisher verification. MSVC /analyze completed with no V3 security finding (six non-blocking pre-existing stack-usage advisories); Clang sanitizers were not installed on this Windows host and remain wired to the optional fuzz/CI build.

See artifacts/package-content-protection/phase-6/qualification-evidence.json.

Exit gate

Complete. All Phase 6 hostile-input, confidentiality, performance, compatibility, and real-time budgets pass in the supported Windows x64 Release configuration. Repository-wide cutover failures and independent review remain CPCA-7 and CPCA-8 work.

Independent Security Review and Release Approval

External review

Validate construction, implementation, operations, and public claims independently before release.

Development and coordination tasks

  • Provide the reviewer with the ADR, byte contract, source, key runbook, threat model, fixtures, fuzz results, performance evidence, and reproducible commands.
  • Request focused review of canonical encoding, signature coverage, key separation, parser bounds, secret handling, downgrade behavior, and extraction-resistance claims.
  • Remediate every release-blocking finding and rerun all affected gates.
  • Freeze compatibility policy, dependency cadence, incident owner, rotation procedure, release checklist, and support escalation.

Approval evidence

  • No unresolved critical/high security findings.
  • Independent reproduction of wrong-key, mutation, symmetric-key-compromise, downgrade, and plaintext-scan evidence.
  • Product/security approval of the exact customer-facing promise and non-goals.
  • Release, incident, migration, and support owners sign off.
External dependency: this gate cannot be self-certified by the implementation author. Assign and schedule an independent reviewer before the release candidate is frozen.

Release gate

The independent report supports the approved claim, all blocking findings are closed, and operational owners approve release.

Definition of Complete

The initiative is complete only when: a normal Practical Sampler export produces a signed V3 package; every supported product path verifies and opens it through bounded worker-side reads; protected plaintext is absent from persistent artifacts; legacy packages remain explicitly unprotected read-only compatibility inputs; all qualification gates pass; and independent review approves the construction and claim.
