Playable Instrument License Iteration

Carry authored license text from the user library into every playable package.

Add Import License File... in authoring project mode, store the selected text as LICENSE.txt at the instrument content root, seal it into the exported .drpkg, and expose a read-only View License command in a loaded Performance package session.

Optional payload Exact authored bytes Authenticated package data Plugin + standalone parity No audio schema change
Recommended delivery: five reviewable slices. Freeze compatibility and expected-red tests first, then storage, package persistence, viewing UX, and release evidence.
Contract

Behavior to freeze before implementation

Authoring mode

  • The File menu shows Import License File... only when authoring is available.
  • The chooser accepts one existing *.txt file.
  • An unsaved project follows the existing background-image precedent: Save As completes first, then import resumes.
  • The destination is the saved instrument root, beside the .drsproj: LICENSE.txt.
  • Replacing an existing license uses a deliberate confirmation and an atomic file replacement.

Performance mode

  • A loaded package that contains a valid license exposes View License in File.
  • Packages without a license do not expose the command.
  • The viewer is read-only, selectable, scrollable, keyboard accessible, and does not extract a temporary file.
  • Package replacement and close clear the previous license so stale legal text cannot remain visible.

Text policy

  • Maximum source size: 1 MiB; package records remain chunked at the existing 64 KiB bound.
  • Require valid UTF-8 text and reject embedded NULs or binary-looking content.
  • Accept an optional UTF-8 BOM. Preserve source bytes exactly in storage and package payload; suppress only the BOM in the displayed string.
  • Do not rewrite line endings or append a newline.

Integrity policy

  • The license is optional for packages that do not declare one.
  • If the manifest declares a license, missing, corrupt, oversized, wrong-kind, or invalid UTF-8 payload data fails package opening before activation.
  • A failed replacement leaves the previously active package and its license intact.
  • The license never participates in DSP, render-model, or realtime audio state.
Architecture

Additive payload, existing container

Follow the background artwork pipeline, but apply stricter legal-integrity validation. Add PerformancePackagePayloadKind::licenseText, PackageV2RecordKind::licenseText = 7, and optional manifest metadata license.payloadId. The logical path is always LICENSE.txt and the media type is text/plain; charset=utf-8.

No package schema bump: the package-v2 TOC already preserves unknown numeric record kinds, manifest parsing tolerates additive fields, and the payload is not required for audio playback. Existing schema-1 and schema-2 packages remain valid; older readers can ignore the additive license record.

Guardrails

Risks and explicit boundaries

Legal text integrity

Never silently omit a declared, malformed license. Export and open must fail with a precise finding so a distributable cannot lose its legal notice unnoticed.

Stale package state

License ownership must follow the same prepare-then-swap transaction as audio payload activation. Do not mutate the active license during failed replacement preparation.

Unbounded UI text

Validate and cap bytes before constructing JUCE strings. The viewer must not read from disk or package storage while painting or on the audio thread.

Scope control

Deferred: multiple legal documents, rich text/Markdown/HTML rendering, localization, license editing, URL detection, extraction, signatures, and mandatory-license policy.

Acceptance

Definition of done

  1. A saved project can import one valid *.txt file as byte-identical LICENSE.txt at its content root.
  2. Export includes that file as an authenticated optional payload without changing audio/runtime schema versions.
  3. New readers fail closed when a declared license cannot be trusted; packages without licenses and existing package fixtures remain playable.
  4. Plugin and standalone Performance File menus expose and display the active package license with a usable read-only viewer.
  5. Package replacement, close, restore, cancellation, and failure paths cannot leak stale license text.
  6. Focused tests, package matrix, UI/smoke/responsiveness tests, realtime checks, release gate, and production VST3 build all pass.
