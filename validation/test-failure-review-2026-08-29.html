Cross-cutting findings

The crash labels are genuine

Windows Application Error events recorded 0xc0000005 for all 20 tests listed as “SEGFAULT.” Nineteen faulted in their statically linked test executable; the VST3 qualification case faulted in Practical Sampler.vst3. CTest did not simply mislabel assertion exits.

Because the original run did not preserve crash dumps, a precise source line cannot yet be assigned. The categorization is based on module/event evidence, test purpose, and focused reruns—not a recovered call stack.

The crash cluster is load/order sensitive

Seventeen quick crash-class cases each passed three consecutive serial runs. The remaining cases supplied mixed evidence: lifecycle stress passed at 1 and 10 cycles; host validation exposed timing flakiness; Sprint 6 hardening passed once and later hung. This pattern is consistent with unfinished asynchronous work, teardown ordering, or resource-pressure handling.

Passing serially does not exonerate the product. A valid integration test that intermittently crashes or hangs under the supported aggregate run is still reporting a release-relevant defect.

The smoke failure is deterministic

tests/src/Phase0SmokeTests.cpp:414–447 confirms a default Performance activation is installed before rendering MIDI through the shared Processor path. The activation precondition passes and the rendered magnitude remains below 0.0001. The likely fault boundary is between bootstrap activation ownership and the active render model/sample data.

The timing failures are test-design defects

WavImportHostValidationTests.cpp uses a single wall-clock sample with a fixed 1500 ms Debug cap. Phase1RuntimeBaselineGuard.cpp compares one generated sample against a checked-in absolute window. Both are vulnerable to cold-cache and machine-load noise and should use controlled, repeated measurements.

Recommended sequence

  1. Enable dump capture first. Configure Windows Error Reporting LocalDumps (or run the aggregate under a debugger) for drs_*.exe and the VST3 qualification host. Preserve PDBs from the exact build.
  2. Instrument bounded shutdown. Log creation, cancellation, completion, and join of prepared-playback, preview, waveform, import, publish, and export workers. Assert that no callback targets a destroyed Processor, facade, controller, or shell.
  3. Fix the deterministic silent bootstrap. Trace note routing through activation selection, render-model ownership, sample lookup, and voice creation after resetSessionStateToDefault().
  4. Repair the two timing gates. Warm up, sample repeatedly, use a median or percentile, record diagnostics, and run performance gates with controlled parallelism.
  5. Split stress qualification from ordinary CI. Keep a short deterministic lifecycle-stress case in the aggregate and schedule the full 100-cycle version separately. This is a lane change, not test removal.
  6. Re-run the aggregate with normal concurrency. Require zero crashes, hangs, assertion failures, and missing executables before calling the checkout green.
