Critical finding 01 · Implementation roadmap

Make DAW recall restore the authored project

Introduce a versioned, project-aware host-state contract that restores the correct authored document, reconnects moved content, and republishes playable state without file I/O or preparation work on the audio thread.

  • Scope: plug-in host save/restore
  • Estimate: 18–25 engineering days
  • Delivery: 4 gated milestones
  • Primary risk: asynchronous host lifecycle

Target outcome

Identity

Recall the right project

A fresh instance identifies the saved .drsproj, validates its project ID and digest, and never silently substitutes the reference instrument.

Continuity

Preserve authored work

Saved projects reopen from disk. Dirty changes round-trip in a bounded project snapshot containing metadata and paths, never sample bytes.

Playback

Republish safely

The restored document uses the existing background preparation pipeline. Audible activation occurs only after all identities match.

Problem statement and boundaries

Current failure

Processor::getStateInformation() exports only drs.presetState. On restore, the processor was already constructed with buildInitialAuthoringProject(); no project locator, authored document, draft revision, or published identity is available to replace it.

In scope

  • A versioned host-session envelope.
  • Saved and dirty-project recall.
  • Moved, missing, changed, and corrupt-content recovery.
  • Legacy preset migration.
  • Thread-safe capture, asynchronous restore, and DAW validation.

Non-goals

  • Do not change drs.presetState semantics.
  • Do not embed audio, .drstrm, prepared buffers, voices, or caches.
  • Do not block a host callback on file I/O or preparation.
  • Do not treat a remembered global path as project identity.

Proposed restore architecture

1 · Host callbackCopy bounded bytes, parse the envelope, and publish an immutable generation-tagged request.
2 · Resolve projectPrefer a dirty snapshot; otherwise locate and validate the saved manifest.
3 · Restore documentReplace model, file binding, selections, revision, saved revision, and dirty status.
4 · Prepare playbackUse the existing snapshot/prepared-playback worker and verify all digests.
5 · ActivateApply staged preset values and activate matching playback at a block boundary.

Host-state contract

Add an outer drs.hostState contract. Nest the existing preset payload unchanged so its strict validation and fixtures remain valid. Freeze exact field names in an ADR.

{
  "schemaName": "drs.hostState",
  "schemaVersion": 1,
  "presetState": { "schemaName": "drs.presetState", "schemaVersion": 1, "...": "unchanged" },
  "projectBinding": {
    "projectId": "stable-id",
    "manifestPath": "relative-or-absolute locator",
    "manifestFileName": "Instrument.drsproj",
    "manifestDigest": "sha256:...",
    "contentRootHint": "optional relocation hint"
  },
  "authoringState": {
    "revision": 17,
    "savedRevision": 14,
    "dirty": true,
    "projectSnapshot": { "...": "bounded .drsproj model; paths only" }
  },
  "publishedState": {
    "revision": 14,
    "projectGeneration": 6,
    "authoredContentDigest": "...",
    "macroSchemaDigest": "...",
    "preparedContentDigest": "verification only"
  }
}

Saved project

Reopen from disk and require expected project ID plus manifest digest before publish. The locator is a hint; identity is authoritative.

Dirty project

Embed the lightweight project model, preserve the file binding and saved revision, and present the restored document as dirty.

Legacy state

Accept raw drs.presetState v1 as legacyUnboundProject. The next save emits drs.hostState v1.

Invalid state

Reject unknown versions, over-budget data, malformed snapshots, and identity conflicts atomically while preserving current valid state.

Threading and real-time rules

Capture

Publish immutable bytes

Serialize after message-thread-owned project, document, preset, or publish changes. getStateInformation() loads the latest immutable block and copies it.

Restore

Queue, do not hydrate

setStateInformation() enforces limits, detects the schema, and submits a request. File I/O and preparation happen elsewhere.

Audio

Activate only

processBlock() sees only fully prepared immutable data. No JSON, filesystem, locks, unbounded allocation, or recovery logic.

Delivery sequence and gates

M1 · Contract provenADR, fixtures, codec, limits, migration, and contract tests.
M2 · Project restoredSaved and dirty checkpoints restore into a fresh processor without UI.
M3 · Playback restoredMatching state prepares asynchronously and activates safely.
M4 · Recovery shippedMoved-content UX, host matrix, concurrency checks, and docs complete.

The estimate assumes one engineer familiar with the authoring and publish contracts. UI and host QA can overlap after M2; M1–M3 remain ordered because they establish identity and threading invariants.

Definition of done

The issue is corrected only when all of these are true

  • A fresh processor restores a non-reference authored project.
  • ID, binding, revisions, dirty state, and selections match.
  • Dirty edits survive without embedding sample audio.
  • Preset values target the restored instrument.
  • Matching published identity activates at a block boundary.
  • Moved content reaches a recoverable Needs Location state.
  • Wrong, changed, corrupt, and oversized inputs do not partially mutate state.
  • Legacy Phase 1 fixtures still load and migrate on next save.
  • Recall works with the editor closed and without modal UI.
  • No file, JSON, lock, or unbounded allocation work enters processBlock().
  • Existing preset, authoring, preview, and publish tests remain green.
  • The REAPER session/recovery matrix passes.
