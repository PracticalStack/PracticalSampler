Large-Instrument Streaming Iteration Plan

An eight-phase engineering iteration to replace whole-instrument PCM residency with bounded, nonblocking sample streaming across authoring preview, playable-package export, and plug-in activation.

Current prepared-playback budget: 512 MiB. The measured resident set is approximately 4.8× that budget before package-decryption and activation copies.

Iteration direction

The work separates the control plane—metadata, routes, validation, preparation, and activation—from the data plane—prefetch heads, page reads, cache residency, and voice consumption. No audio-thread operation may open a file, allocate memory, wait on a mutex, decrypt content, or request a blocking read.

  • 01Bound memory before work begins. Every load path must know its estimated and configured residency before decoding or caching.
  • 02Make partial readiness explicit. Metadata-ready, head-ready, playable, degraded, and failed are separate states.
  • 03Stream once, use everywhere. Authoring WAVs and packaged content share the same sampler-facing data-source contract.
  • 04Preserve deterministic playback. Streaming changes storage and scheduling, not route selection, gain, articulation, round robin, or DSP semantics.

Preliminary work · mandatory stabilization

Stabilize and Bound

Stop the current large-instrument paths from freezing the interface or silently entering a non-playable state while the streaming architecture is built.

Phase outcome

Selected-scope preview performs only selected-scope work, background preparation never monopolizes the coordination mutex, and any request that exceeds resident-mode policy is rejected before decoding with actionable guidance.

Work packages

STR-000Scope preview before prepared-sample realization
  • Move selected-zone and selected-group filtering ahead of PreparedPlaybackService::prepare().
  • Build the minimum dependency closure for crossfade neighbors, round-robin peers, release triggers, group routing, and inherited DSP.
  • Keep current-draft preview as an explicit full-scope request.
  • Retain deterministic digests for equivalent scoped input.
Deliverable: scope-aware snapshot/preparation request plus selected-zone and selected-group regression coverage.
STR-001Remove long-running work from the worker coordination mutex
  • Restrict workerMutex to queue, cache-index, completion, and status publication transitions.
  • Perform fingerprinting, decoding, file reads, digest construction, and cancellation checks outside the mutex.
  • Publish progress through immutable/atomic snapshots or bounded critical sections.
  • Prove status polling, cancellation, shutdown, and project-close remain responsive during slow I/O.
Deliverable: lock-scope audit, concurrency tests, and a message-thread latency trace.
STR-002Enforce resident-preparation admission and honest load states
  • Estimate decoded bytes from inspected frames × channels × float width before sample realization.
  • Reject requests above the configured resident budget; do not treat the current 512 MiB threshold as telemetry-only.
  • Differentiate metadata loaded, playback deferred, playable, and streaming required in processor and UI state.
  • Prevent metadata-only package opening from reporting successful playable activation.
Deliverable: typed admission result, user-facing status mapping, and over-budget fixtures.

Dependencies

  • Existing immutable snapshot and preview-scope contracts.
  • Reliable metadata inspection without full PCM decode.
  • Current cancellation-generation semantics.

Architecture contract

Sample Data Source Contract

Replace the renderer’s assumption of fully decoded channel vectors with one immutable sampler-facing contract that can represent resident, file-backed, and package-backed sample content.

Phase outcome

The render model references stable sample descriptors and bounded read views rather than owning all decoded PCM. Existing tiny resident instruments continue to work through a resident implementation of the same contract.

Work packages

STR-100Define immutable sample identity and storage descriptors
  • Define canonical source identity, format, frame count, channel count, sample rate, data layout, head range, page geometry, checksum identity, and source generation.
  • Use 64-bit offsets and sizes throughout.
  • Separate authored source provenance from runtime storage location.
Deliverable: versioned SampleDataSourceDescriptor and validation contract.
STR-101Introduce resident and paged source interfaces
  • Provide bounded, non-owning frame views suitable for the audio callback.
  • Represent resident-head availability, page readiness, end-of-sample, and source failure without exceptions.
  • Keep allocation, I/O, locking, and ownership transitions outside callback methods.
Deliverable: source interface, resident adapter, fake deterministic paged adapter.
STR-102Refactor prepared and render models around descriptors
  • Replace mandatory decodedSampleData ownership in PreparedPlaybackSampleHandle and SamplerRenderSample.
  • Retain backward-compatible resident payloads for small fixtures during migration.
  • Update digest/equality semantics to exclude transient cache state and include source generation.
Deliverable: dual-mode prepared/render model with unchanged route semantics.
STR-103Define cache, lease, and retirement ownership
  • Specify who owns heads, pages, page tables, file/package handles, leases, and retired generations.
  • Prohibit cache eviction while any voice lease references a page.
  • Define bounded asynchronous reclamation at generation cutover.
Deliverable: lifecycle state machine and ownership invariants.

Dependencies

  • Phase 0 admission and scope-aware preparation.
  • Existing activation-generation retention rules.
  • Current render-model validation suite.

Authoring data plane

Real Authoring WAV Streaming

Implement the first production data-source backend by reading seekable WAV sample heads and pages directly from authored source files on background I/O workers.

Phase outcome

A large SFZ draft can become preview-capable without decoding every source. Selected-zone preview primes the chosen sample’s head, then pages forward through a bounded cache.

Work packages

STR-200Build WAV metadata and byte-range mapping
  • Parse RIFF/RF64 chunks and map logical float frames to PCM byte ranges without full decode.
  • Support current mono/stereo PCM bit depths and floating-point WAV policy.
  • Validate truncation, unsupported compression, malformed chunks, and source mutation.
Deliverable: seekable WAV descriptor builder with RF64-safe offsets.
STR-201Implement bounded background page reads and conversion
  • Read source byte ranges on worker threads and convert only requested frames to float32 cache pages.
  • Deduplicate pending reads by source generation and page index.
  • Apply queue depth, byte, and concurrency limits; prioritize head and imminent voice pages.
Deliverable: real WAV page provider and deterministic scheduling tests.
STR-202Prime resident heads for preview
  • Default to the existing 16 KiB head policy, with an explicit frame-aligned clamp.
  • Prime only the scoped preview dependency set.
  • Report head-ready separately from full page availability.
Deliverable: scoped head-preparation pipeline and startup metrics.
STR-203Detect source mutation and recover cleanly
  • Bind opened sources to size, modification stamp, and fingerprint generation.
  • Invalidate stale pages asynchronously when a source changes.
  • Keep the last known-good preview active when a newer source generation fails.
Deliverable: source-generation invalidation and recovery coverage.

Dependencies

  • Phase 1 data-source and lease contracts.
  • JUCE WAV reader metadata or a small seekable WAV parser.
  • Existing project source validation service.

Realtime consumption

Paged Sampler Rendering

Teach the production sampler voice and playback context to render continuously across resident heads and ready pages without blocking the audio callback.

Phase outcome

Voices start from resident heads, consume frame-aligned page views, request future pages through a lock-free intent queue, and degrade safely when data is late.

Work packages

STR-300Refactor SamplerVoice around bounded frame views
  • Remove direct indexing into mandatory normalized-channel vectors.
  • Support interpolation across head/page boundaries and mono/stereo layouts.
  • Preserve sample start, loop, release, pitch, pan, gain, and generation semantics.
Deliverable: paged voice kernel with resident-mode parity tests.
STR-301Implement look-ahead and page-request intent transport
  • Calculate next-page demand before the current view is exhausted.
  • Push bounded primitive intents from audio to the I/O scheduler.
  • Deduplicate, prioritize, and cancel obsolete generation requests off-thread.
Deliverable: bounded request ring and scheduler integration.
STR-302Define late-page behavior
  • Never wait on a page in the callback.
  • Choose and document the v1 policy: bounded silence for missing frames with diagnostic accounting; resume only when musically safe.
  • Track underruns per source, voice, and activation without logging from audio.
Deliverable: deterministic underrun policy and offline fault-injection suite.
STR-303Bound cache eviction and voice leases
  • Use a fixed byte/page budget and LRU-style eviction outside audio.
  • Pin resident heads and actively leased pages.
  • Reclaim retired generations incrementally with backlog diagnostics.
Deliverable: production page cache with pressure and retirement metrics.
STR-304Preserve multi-voice and trigger behavior
  • Exercise polyphony, velocity crossfades, round robins, release samples, pedal triggers, choke groups, and rapid generation cutover.
  • Prime shared pages only once when several voices hit the same sample.
Deliverable: streamed performance-engine conformance matrix.

Dependencies

  • Phase 1 source/lease contract.
  • Phase 2 real page provider.
  • Existing voice generation and realtime-guard suites.

4
Portable storage

Package Format v2

Replace the single encrypted runtime-stream blob with independently addressable and authenticated records that can be opened and read by range.

Phase outcome

A package reader can validate metadata, open the package data source, prime heads, and decrypt requested records without holding the complete payload or ciphertext in memory.

Work packages

STR-400Specify v2 record and index layout
  • Define independently sealed head/page records with 64-bit package offsets, plaintext sizes, sealed sizes, source/page identities, and checksums.
  • Keep manifest, runtime instrument, and stream index independently readable.
  • Bind authenticated data to package, source generation, record kind, and page index.
Deliverable: package v2 schema and binary-layout specification.
STR-401Add range-capable crypto and reader APIs
  • Replace by-value multi-gigabyte plaintext/ciphertext requests with bounded record operations.
  • Read, authenticate, decrypt, and verify one record at a time.
  • Keep corruption classification precise: header, TOC, record authentication, checksum, or compatibility.
Deliverable: bounded package record reader and crypto interface.
STR-402Implement package-backed sample data source
  • Map sampler source/page requests to v2 TOC records.
  • Reuse the Phase 2 scheduler/cache and Phase 3 voice path.
  • Keep the package handle and immutable TOC alive for the activation generation.
Deliverable: package page provider with corruption and cancellation tests.
STR-403Define v1 compatibility and migration policy
  • Continue loading small v1 packages within a strict resident-size ceiling.
  • Reject oversized v1 packages with a clear re-export requirement.
  • Do not silently rewrite package files during load.
Deliverable: compatibility matrix and reader dispatch policy.

Dependencies

  • Phase 1 storage descriptor.
  • Phase 3 real cache and voice consumption.
  • Current deterministic package corpus and failure taxonomy.

Bounded authoring output

Streaming Export

Write playable packages incrementally so compilation, sealing, and final assembly never require whole-payload vectors or multiple payload-sized copies.

Phase outcome

Export converts one bounded source chunk at a time, seals v2 records as they are produced, writes directly to a staged package, and atomically publishes the completed file.

Work packages

STR-500Build a bounded compile-to-package pipeline
  • Decode/convert source audio in fixed-size chunks rather than full samples where supported.
  • Emit aligned head/page records directly to the package staging stream.
  • Bound conversion, plaintext, ciphertext, and output buffers independently.
Deliverable: incremental runtime-stream compiler and package writer.
STR-501Finalize TOC and package header safely
  • Accumulate only bounded record metadata in memory.
  • Finalize or patch the header/TOC after payload writing using an explicit staging format.
  • Verify the staged file before rename to the requested output path.
Deliverable: crash-safe staged write and atomic publication.
STR-502Make progress and cancellation proportional
  • Report source, record, and byte progress without message-thread file work.
  • Check cancellation at bounded read/convert/seal/write boundaries.
  • Remove incomplete staging files through the existing recoverable cleanup policy.
Deliverable: responsive export lifecycle with deterministic cancellation.
STR-503Verify package output during export
  • Validate manifest/index/TOC consistency and record ranges before completion.
  • Sample-check record authentication and checksums without a second full-file read.
  • Persist export metrics for qualification.
Deliverable: streaming verification pass and export evidence report.

Dependencies

  • Phase 4 v2 writer and record crypto.
  • Current compile plan and package manifest semantics.
  • Existing export service ownership/cancellation model.

Runtime lifecycle

Deferred Plug-in Activation

Complete the two-stage package-open workflow so metadata appears quickly, sample heads prepare in the background, and audio activation occurs only when the package is actually playable.

Phase outcome

The plug-in transitions through explicit metadata-ready, preparing-heads, playable, active, degraded, and failed states. A stable metadata-only open is no longer a terminal dead end.

Work packages

STR-600Define the staged package session state machine
  • Separate metadata acceptance, data-source open, head preparation, render-model construction, pending activation, and audio cutover.
  • Make terminal and retryable failures explicit.
  • Keep the previous active instrument sounding until the new activation is eligible.
Deliverable: typed package-session lifecycle and UI projection.
STR-601Connect metadata-only open to deferred data-source preparation
  • Retain the package path, validated TOC, runtime metadata, and cancellation identity.
  • Open the package-backed data source and prime required heads asynchronously.
  • Queue render-model construction when admission and head readiness succeed.
Deliverable: live continuation from metadata-ready to playable.
STR-602Activate at the audio block boundary
  • Exchange only the prepared generation token/pointer through the existing activation slot.
  • Retain old sources and pages until all old-generation voices retire.
  • Publish audible readiness only after successful callback-side cutover.
Deliverable: deferred activation integration with generation retention.
STR-603Implement cancel, close, recall, and replacement behavior
  • Cancel in-flight open/preparation when the project closes or a newer package replaces it.
  • Restore package locators through host state without blocking setStateInformation() or processBlock().
  • Expose missing-package and incompatible-v1 recovery guidance.
Deliverable: lifecycle, host-recall, and rapid-replacement stress coverage.
STR-604Surface meaningful progress and diagnostics
  • Report metadata, head, cache, and activation progress separately.
  • Show actionable failure category and source/page identity.
  • Avoid implying that all sample data must load before performance begins.
Deliverable: plug-in/standalone parity for status and recovery.

Dependencies

  • Phase 3 streamed render activation.
  • Phase 4 package-backed source.
  • Phase 5 valid v2 package output.

Evidence and release gate

Qualification and Release

Prove bounded memory, responsive lifecycle behavior, realtime safety, deterministic playback, and package integrity on the actual large piano and a scale-focused regression corpus.

Phase outcome

The iteration closes only when the Salamander instrument imports, previews, exports, loads, activates, and survives sustained performance within agreed budgets on supported systems.

Work packages

STR-700Create scale-focused deterministic fixtures
  • Add synthetic/sparse backends representing multi-gigabyte sources without checking huge binaries into the repository.
  • Cover >4 GiB offsets, 641+ sources, 1,704+ routes, long samples, and cache-pressure patterns.
  • Retain small real WAV/package corruption fixtures.
Deliverable: CI-safe large-scale fixture toolkit.
STR-701Run the Salamander end-to-end qualification matrix
  • Measure import, selected-zone preview, selected-group preview, current-draft preparation, export, metadata open, head-ready, activation, first note, and sustained play.
  • Capture peak working set, cache residency, read latency, underruns, cancellation latency, and callback budget.
  • Test warm/cold filesystem cache and at least one constrained-storage profile.
Deliverable: signed Salamander qualification report and traces.
STR-702Execute realtime and lifecycle soak
  • Run rapid notes, pedals, crossfades, round robins, repeated package replacement, host save/restore, transport churn, editor open/close, and shutdown.
  • Inject slow reads, failed reads, corrupt pages, cancellation, and cache pressure.
Deliverable: zero-violation realtime/lifecycle soak evidence.
STR-703Close compatibility, documentation, and observability
  • Document v1/v2 package support, re-export behavior, budget defaults, and failure recovery.
  • Finalize diagnostic labels and support bundles.
  • Update release notes and internal architecture references.
Deliverable: support matrix, migration notes, and operational diagnostics.
STR-704Run release audit and remove transitional paths
  • Audit for whole-payload reads, payload-sized copies, full-corpus preview decode, synthetic production pages, and misleading readiness strings.
  • Remove compatibility bridges that are no longer needed; retain only the intentional small-resident path.
  • Record accepted residual risks and owners.
Deliverable: release checklist with source audit evidence.

Dependencies

  • All prior phase gates complete.
  • Release build and host qualification environments.
  • Licensed internal access to the Salamander corpus.

Iteration-level decisions and boundaries
IDDecisionRationale
D-01Keep a small-instrument resident path behind the common source contract.Avoids adding streaming latency and complexity where bounded residency is demonstrably safe.
D-02Use 16 KiB heads and 64 KiB pages as starting defaults, not immutable format rules.Matches existing compile metadata while permitting evidence-driven tuning by load profile.
D-03Version the package format for independently authenticated records.The current monolithic authentication boundary cannot support bounded random-access loading.
D-04Do not broaden this iteration into new codecs, resampling, or DSP behavior.The objective is storage/scheduling scalability while preserving existing playback semantics.
D-05Treat memory and responsiveness budgets as admission policy, not reporting-only metrics.Failing early is safer and more diagnosable than paging, freezing, or crashing after work begins.

Execution controls

Sequencing rule

  • Phase 0 may land independently and should ship before the streaming cutover.
  • Phases 1–3 form the authoring vertical slice.
  • Phases 4–6 form the packaged-instrument vertical slice.
  • Phase 7 begins incrementally but owns final release qualification.

Change discipline

  • Keep resident baseline tests green at every phase.
  • Add one typed seam before removing its legacy path.
  • Do not mix callback changes with package-format changes in one unreviewable patch.
  • Require evidence artifacts at every gate.

Primary risks

  • Page misses under high polyphony or constrained storage.
  • Lifetime errors across rapid activation replacement.
  • Package v2 scope expanding beyond bounded streaming needs.
  • Small fixtures passing while large-scale behavior remains untested.

Iteration completion condition: the Accurate Salamander Grand Piano can be imported, scoped-previewed, prepared, exported, opened, activated, and played in DRS without whole-instrument PCM residency, UI stalls, audio-thread blocking, unbounded memory growth, or indefinite “loaded but not playable” state.
