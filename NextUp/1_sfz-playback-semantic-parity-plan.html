SFZ Playback Semantic Parity Plan

Decent Rhapsody Studio · High-level implementation and qualification plan

Confirmed defect: the standard Accurate Salamander SFZ sounds chorused after DRS import and packaging, while the minimum SFZ does not. The standard file contains optional pseudo-resonance and mechanical layers controlled by SFZ trigger and MIDI CC conditions. DRS currently imports their regions without preserving those conditions, making some optional layers play unconditionally.

Goals

  • Prevent unsupported SFZ conditions from changing the sound silently.
  • Make a packaged instrument reproduce the supported semantics of its source SFZ.
  • Provide safe, explicit behavior when an SFZ uses features DRS cannot yet reproduce.
  • Add route-level and rendered-audio parity qualification.
  • Preserve the qualified package, streaming, and real-time playback architecture.

Confirmed Failure Pattern

SFZ content Regions Expected default behavior Current DRS behavior
Normal piano layers 1,408 One velocity-matched region per note Imported and played
Pseudo pedal resonance 135 Disabled unless its CC and sustain conditions are met Imported as ordinary sustain zones; often two extra voices per note
Sampled release 69 Release-triggered and controller-gated Only partially represented
Hammer noise 88 Release-triggered and controller-gated Only partially represented
Pedal action 4 Pedal-event and random-policy controlled Conditions are not reproduced completely

The immediate audible defect is the pseudo-resonance layer. The source describes it as a detune effect; making it permanently active creates the observed chorus character.

Guiding Rules

  • Unsupported selection conditions must never degrade into unconditional playback.
  • Import success means the projected instrument is audibly safe, not merely that every region was retained.
  • Conditional regions are included only when DRS can represent their complete eligibility rule.
  • Lossy import decisions are explicit, summarized, and reversible before project mutation.
  • Package export preserves the approved native project; it does not reinterpret SFZ semantics.
  • Performance is qualified separately from semantic parity so neither can mask failures in the other.

Implementation Phases

Phase 1 — Establish semantic dependency analysis

Purpose: determine whether each region can be projected safely before creating a native zone.

  • Classify region eligibility dependencies, including CC ranges, pedal state, trigger event, random policy, switches, and controller defaults.
  • Distinguish harmless unsupported presentation metadata from sound-critical unsupported behavior.
  • Mark regions with incomplete sound-critical semantics as unsafe to project unconditionally.
  • Include inherited <global>, <master>, and <group> conditions in the classification.

Phase 2 — Add a safe import policy

Purpose: stop the chorus defect before broader SFZ controller support is complete.

  • Do not create unconditional zones from conditionally gated regions when their conditions are unsupported.
  • Offer an explicit review choice to omit unsupported conditional regions or cancel the import.
  • Summarize omitted regions by feature and source section.
  • Default to the sound-safe option; never silently retain a behavior-changing approximation.
  • For the Salamander standard SFZ, initially omit the 296 optional auxiliary regions and retain the 1,408 normal piano regions.

Phase 3 — Implement core sound-parity opcodes

Purpose: close the most important differences between DRS and mature SFZ players.

  • Support controller conditions such as loccN, hiccN, on_loccN, and on_hiccN.
  • Preserve controller defaults such as set_ccN.
  • Represent note-on, note-off/release, pedal-down, and pedal-up eligibility explicitly.
  • Support group_volume with correct scope inheritance.
  • Support tune in cents in addition to root-key transposition.
  • Implement or deliberately approximate amp_veltrack with a documented native control law.

Phase 4 — Restore optional Salamander behavior

Purpose: re-enable auxiliary layers only after their complete conditions are supported.

  • Enable pseudo pedal resonance only when CC23 and sustain conditions are satisfied.
  • Apply its intended group attenuation and fine tuning.
  • Enable sampled release and hammer noise only on the correct release events and controller states.
  • Enable pedal-action samples only on matching pedal transitions.
  • Implement a supported random-region policy or keep the random pedal variants safely omitted.

Phase 5 — Replace count-based qualification with semantic qualification

Purpose: test what should sound, not just what was imported.

  • Remove the assumption that retaining all 1,704 regions is automatically correct.
  • Assert eligible route counts for representative notes, velocities, controller states, and trigger events.
  • At the default controller state, assert exactly one middle-C note-on route.
  • With resonance enabled and sustain down, assert only the intended additional routes and gains.
  • Verify release and pedal routes remain silent until their required events and controllers occur.
  • Add deterministic offline renders and compare peak, RMS, duration, spectral profile, and sample-aligned error against approved references.

Delivery Sequence

  1. Safety patch: dependency classification, omission of unsafe conditional regions, import review summary, and regression coverage for the confirmed chorus defect.
  2. Core parity patch: controller conditions, defaults, event eligibility, group gain, fine tuning, and velocity tracking.
  3. Auxiliary behavior patch: conditional resonance, release, hammer, and pedal-action playback.
  4. Qualification patch: route-state matrices, rendered-audio references, and updated large-instrument release gates.

Acceptance Gates

  • The standard and minimum Salamander imports sound equivalent under their shared default piano-only state.
  • Middle C at the default CC state starts exactly one ordinary piano route.
  • No unsupported conditional region becomes an unconditional native zone.
  • Enabling resonance produces the intended controlled layer rather than a permanently active chorus.
  • Fine tuning and group gain survive import, project persistence, preparation, package export, and package reopen.
  • Import review reports every omitted or approximated sound-critical feature.
  • Package export and import remain deterministic and performant.
  • Host MIDI, streaming, page-cache behavior, audio callback timing, and real-time safety remain within their existing qualified limits.
Primary guardrail: fix the SFZ-to-native semantic projection and qualification rules. Do not modify the working package streaming architecture to compensate for incorrectly projected zones.

Status: confirmed defect with proposed high-level remediation plan. The minimum Salamander SFZ remains the temporary parity-safe import option.
